## 1. 结论先行

1. **既有真机数据确实只跑了 1 个信号**：T1-9 / T1-10d / T1-10e 的性能数据全部基于单信号
   （`launch_start`，calib-v1）；设备产物随后扩到 **7 个信号**，但**没有做过 7 信号的真机性能测量**。
   这是当前性能认知的最大缺口。
2. **桌面测量：7 信号 = 单信号的约 3.85×**（38.04ms vs 9.88ms，同一批 51 帧），近似线性但有折减
   （各信号窗口/模板大小不同，单信号均值 9.88→5.43ms）。
   按 T1-10d 真机单信号识别段 ≈294–308ms 粗推，**7 信号真机可能在 ~1.1s/帧量级**——必须实测。
3. **耗时构成：粗搜 ≈79%、精搜 ≈20%、前缀和构建 ≈1%**。
   → 这**推翻了 T1-10e 里"精搜是瓶颈"的假设**：真正的大头是**粗搜**（网格点数 × 采样点数）。
   → 也解释了为什么"部分和剪枝"只有 ×1.06：它只作用于精搜那 20%。

## 3. 由数据推导的优化方向（按性价比排序）

粗搜成本 ≈ **网格点数 × 采样点数** =（窗口位置数 / 网格步长²）×（模板像素 / 采样步长²）。
据此，可选手段：

1. **按状态启用信号子集（收益最大，约 3.5–7×）**：当前状态已知时只检测「可能转移到的状态」的信号；
   未知 / 状态变化 / 周期性兜底时全扫。代价：状态机需提供候选集，且要有兜底策略避免漏检。
2. **收紧搜索窗口（约 2×，算法零风险）**：当前窗口 = 选区各向外扩 1 个选区尺寸（约 9× 选区面积）。
   若外扩系数改为 0.5（约 4× 面积），位置数约降一半 → 粗搜同比例下降；代价是标志位移容忍度下降，
   需重新标定并复跑 A7 指标。
3. **多尺度粗搜（约 2–3×）**：在 1/2 尺度上粗搜（成本 ÷4），候选回原尺度精搜（邻域随尺度误差增大，
   需相应减少锚点数 K 以抵消）。代价：K 减小会削弱竞争峰覆盖（影响 §5-2 不可信判定），需评估。
4. **工程侧：降分配 / 降带宽（收益未知，可能 2–5×，只能真机验证）**：
   - 设备/桌面倍差达 ×27（T1-10d），远超同代 CPU 的合理差距，提示瓶颈可能在**内存与 GC**而非乘加：
     每帧灰度 ByteArray（1440×3168 ≈ 4.5MB）+ 每信号前缀和两个 LongArray（窗口约 393×111 ≈ 1.4MB），
     7 信号时单帧分配量约 10MB 级；
   - 手段：灰度帧缓冲复用、前缀和改 IntArray 并复用、按窗口区域裁剪（已做）、避免逐帧大对象分配。
5. **增大网格步长 / 更稀疏采样（1.3–1.4×，T1-10e 已测）**：收益有限，且 3×3 采样有位置漂移，已决定不采纳。

## 4. 下一步建议（待用户确认）

1. **先补真机 7 信号基线**（当前最重要缺口）：装机后在真实会话跑长跑，取连续 100 帧满窗统计，
   得到 7 信号下的实际 P95（预计 ~1s 量级）。这一步决定后续优化的目标量级。
2. 同步推进 4（工程侧降分配，改动局部、语义不变、可单测保障），用真机对照验证。
3. 再评估 1（按状态启用子集，收益最大但需状态机配合与兜底设计）。
4. 2（收紧窗口）需重新标定，可随下一轮标定补充一并处理。
