# MasterMechanic 需求文档

> 本文档描述 MasterMechanic 要实现什么，全文只回答「程序应在什么条件下做什么、怎么算做成了、失败时如何收场」。
>
> 采用哪种画面感知手段、哪种输入注入途径、参数取什么值，由实现者自行研究并验证，但必须满足 §5 的要求。

---

## 1. 目标

### 1.1 要解决的问题

玩家在《王者荣耀》的王者农场里有两类反复动作，程序要替他消掉：

| # | 痛点 | 期望 |
| --- | --- | --- |
| 1 | 活动弹窗反复出现，必须手动关掉 | **自动处理，看到就消掉** |
| 2 | 有多个不同区服的小号，要挨个切过去、进农场、拜访指定好友 | **配置一次（预设），之后每点一次就自动跑完一个账号** |

第 2 类是本项目的核心。手动完成一个账号需要「退出农场 → 退出登录 → 换区 → 选择服务器 → 登录游戏 → 进入农场 → 打开好友列表 → 拜访指定好友的农场」整整一串操作，账号多了就是大量重复点击。

> **为什么不是"一次点完全部账号"（2026-09-16 / 09-19 用户口径）**：用户的真实场景是"在同一位好友的农场里，
> 轮流换不同区服的小号来看他"，**一次一个账号**够用；把多个账号排成一条自动队列反而不好中途处理
> （比如想先祝个福再换下一个）。因此**一次执行只跑一条**，要下一个账号就再点一次菜单。

### 1.2 两种工作模式

| 模式 | 说明 | 谁发起 |
| --- | --- | --- |
| 常驻守护 | 自动关闭活动弹窗，长期在后台待命 | 程序自主 |
| 一键跑号 | 按**预设**（服务器策略 + 好友）跑完**一个**账号：换号 → 登录 → 进农场 → 拜访该好友 | 用户在悬浮窗菜单点一次 |

两种模式都要求：**游戏不在前台时，一律不识别、不点击。**

### 1.3 前提与范围外

| 项 | 说明 |
| --- | --- |
| 系统 | **Android 14 及以上**，**不需要 root**（口径修订：2026-10-01 用户确认「以现状最低支持版本为准」，原写 9.0+；来由与代价见 `docs/progress.md` 第 383 条） |
| 授权 | 画面采集与输入模拟的授权由用户在系统层面自行授予，可随时撤销；缺失时必须明确提示，不得静默失败 |
| 屏幕 | 尺寸与密度由用户设备决定，程序**不得绑定任何具体分辨率或密度** |
| 不涉及 | 不读取游戏内存、不注入游戏进程、不修改或拦截网络、不篡改客户端 |
| 不涉及 | 不输入任何账号凭据。跑号切换的是**同一登录账号下的不同区服**，不涉及登录账号本身的切换 |
| 不涉及 | 本版本不实现「祝福」逻辑（点到指定好友的「拜访」即算完成，见 §7） |
| 账号前提 | **不再要求**（2026-09-29 用户口径）：全新号（新手号）上登录后会出现「新手引导 / 新手大厅」两个界面 —— 由 **FR-02 自动关闭**，不需要先手动打完一局 |

## 2. 界面状态

### 2.1 状态清单

程序需要能分辨下列界面。「界面标志」指页面上可被辨认的稳定视觉元素；识别以「界面上是否存在该标志」为单位。

| 状态 | 判定依据（界面标志） | 常驻守护下 | 跑号流程下 |
| --- | --- | --- | --- |
| 启动页 | 「开始游戏」「换区」 | 等待 | 执行换区、登录 |
| 服务器列表 | 「选择服务器」 | 等待 | 选择配置指定的区服 |
| 大厅 | 对战 / 排位 / 农场入口（任一命中即为大厅） | 等待 | 进入农场 |
| 农场 | 农场标志 | 等待 | 打开好友列表 |
| 好友列表 | 好友列表标志 | 等待 | 定位并拜访目标好友 |
| 好友的农场 | 拜访后进入的农场 | 等待 | 视为该账号完成 |
| **设置页** | 游戏内设置界面的标志 | 等待 | **退出登录时途经**（点开设置入口后） |
| **退出登录确认框** | 确认弹窗的标志 | 等待 | **退出登录时途经**（确认后回到启动页） |
| **返回场景确认框** | 「请选择需要返回的场景」弹框的标志 | 等待 | **退出农场时途经**（选「返回大厅」后回到大厅） |
| **新手引导** | 该页面上的一块稳定标志（**只在新手号出现**；登录后、活动弹窗之前） | **自动关闭**（任何阶段，见 FR-02） | **自动关闭**（任何阶段，见 FR-02） |
| **新手大厅** | 该页面上的一块稳定标志（**只在新手号出现**） | **自动关闭**（任何阶段，见 FR-02） | **自动关闭**（任何阶段，见 FR-02） |
| 活动弹窗 | 弹窗关闭控件（需覆盖多种样式） | **自动关闭**（任何阶段，见 FR-01） | **自动关闭**（任何阶段，见 FR-01） |
| 未知 | 以上均不命中 | 不操作，提示用户 | **暂停并提示用户** |

> **设置页 / 退出登录确认框 / 返回场景确认框（2026-09-19 用户确认新增）**：退出登录与退出农场都不是
> 一次点击就能完成的，中间要经过游戏内的设置界面、以及两个确认弹框。这些屏**必须有独立标志**，
> 否则「点完设置入口有没有进去」「点了返回之后到底到了哪」都无从验证，只能盲点（违反 FR-04 的硬性要求 1）。

### 2.2 状态稳定性

状态切换不得由单次识别结果驱动：**连续 2 次**命中才进入该状态，**连续 3 次**未命中才离开该状态，连续 3 次未命中任何标志才判为未知。

进入与退出用不同阈值，用于抑制画面抖动导致的误判。

## 3. 功能需求

### 3.1 自动异常处理

这两类是程序自主执行的，不需要用户发起。

#### FR-01 活动弹窗自动关闭

| 项 | 内容 |
| --- | --- |
| 触发 | **任何阶段**每轮**最高优先级**，先于该阶段的其他识别。弹窗自点击「开始游戏」之后出现（FR-04 第 6 步起）；**实测其出现可延续到进入大厅之后**（2026-09-13），故不受阶段限制，**常驻守护待命期间同样检查** |
| 做什么 | 识别弹窗的关闭控件并点击；必要时辅以「关闭」「跳过」等文字标志 |
| 搜索范围 | **仅屏幕右上角局部范围**，不得全屏搜索 |
| 成功判据 | 弹窗**不再出现**即视为完成（连续数轮未命中）。**不逐次判定"单次点击是否奏效"**——实测表明「点击后仍命中」无法区分「弹窗没关掉」与「换了一个新弹窗」（2026-09-13 真机） |
| 失败处理 | **同一段弹窗内点击次数设上限**：达到上限即停止点击并记录，弹窗消失后复位。该上限只用于兜底「**锚点未命中关闭控件**」（宁可漏关，不可错点），**不作为单次点击的成败判据** |

> 弹窗遮挡画面、阻断全部识别，且关闭控件位置固定、后果可逆，因此是唯一允许「看到就点」的一类。

#### FR-02 新手引导 / 新手大厅自动关闭（**2026-09-29 恢复**）

| 项 | 内容 |
| --- | --- |
| 触发 | **任何阶段**；**只在新手号出现**：登录之后、活动弹窗之前（也可能出现在更早的加载之后）。**声明顺序排在活动弹窗之前**（2026-09-29 用户口径："新手两屏出现在活动弹窗之前"⇒ 万一同时命中，先解决新手这屏） |
| 做什么 | 识别该页面的**关闭 / 跳过 / 退出**控件并点击（每页一个，逻辑与 FR-01 **完全同一套闭环**：命中即点、段内次数与总时长上限、段结束复位、观察窗 / 整帧变化 / 决策帧龄 / 开火前复眼，一处不改） |
| 搜索范围 | 由标定产物给出该控件的锚点窗口（与 FR-01 的"仅右上角"不同：新手页的关闭控件**可能在屏幕任意位置**，所以靠标定框定，不靠硬编码区域） |
| 成功判据 | 该页面**不再出现**即完成（连续数轮未命中）；同样**不逐次判定"单次点击是否奏效"** |
| 失败处理 | 与 FR-01 相同：达到上限即停手并记录，页面消失后复位（"宁可漏关，不可错点"） |
| 点击来源 | 审计里记 **FR-02**（与 FR-01 分开，见 §4） |

> **为什么恢复**：2026-09-13 移除它的前提是"投入使用的账号都先打完一局"（见 §1.3 原「账号前提」）；
> 现在确实用到了**全新号**，两个界面又出现了 —— 正是当时写下的"**恢复条件**"（"若后续出现无法先打完一局的账号，需重新评估是否恢复本条"）。
>
> **与 2026-09-13 那版的差别**：原名叫「自动**返回**」，现在按用户口径做成「自动**关闭**」——
> 行为完全对齐 FR-01（点掉挡屏的东西），不再为它单开一套"返回"逻辑。
>
> ⚠ **新手大厅不是「大厅」**：它上面没有设置入口 / 农场入口这些跑号要用的东西，因此读成「被遮挡」
> 而不是 `Ready(LOBBY)`（读成大厅会让第 3 / 7 步去找不存在的按钮）。

### 3.2 小号跑号（核心功能）

#### FR-03 跑号配置（**2026-09-16 已按用户决定移除**）

> **本条已废止。** 用户决定："跑号 / 巡查原本只是测试用途，移除。"
> 原因：跑号清单是「**一个好友 → 多个区服**」的映射表，从菜单上点「拜访」时**定位不到具体是哪个好友** ——
> 而用户最高频的场景是"在同一个好友的农场里轮流换不同服务器的小号来看他"。
>
> **替代（见 FR-07 的「拜访规则」）**：改为一份**预设**＝「服务器选择策略（**顺序轮换** / 指定某区服）+ 指定好友」，
> 菜单一级点一次就执行"换号 + 拜访"整条流程；预设**可在悬浮窗内直接编辑**（用户口径：不能逼用户切回 App 去配）。
> 数据文件 `files/preset/visit.txt`（`mm-visit-preset` v1）。原实现及 6 个测试文件已于同日删除（共 14 个文件）。
>
> 下表仅作**历史存档**：

| 项 | 说明 |
| --- | --- |
| 跑号项 | 每项 = **一个区服名称 + 一个目标好友名称** |
| 顺序 | 按列表顺序依次执行 |
| 校验 | 区服名称与好友名称均不得为空 |
| 重复 | 允许同一区服重复出现（例如同一区服拜访多个好友） |
| 编辑 | 支持增、删、改、调整顺序、整体清空 |

#### FR-10 服务器清单

换号时要挑「切到哪台服务器」，这份清单就是挑选范围（见 FR-07「换号」）。**在 App 内手工维护。**

| 项 | 说明 |
| --- | --- |
| 条目 | **平台（微信 / QQ）+ 区号 + 区服名称 + 角色名 + 等级**；**除区服名称外都可留空**（平台与区号 2026-09-14 追加） |
| 顺序 | 有序；「按顺序切到下一个」即按本清单顺序 |
| 定位 | **只有区服名称参与定位**（到界面上找它，找不到或不止一个就停下）；平台、区号、角色名与等级**只用于辨识**（帮用户认出哪个是自己的小号、一眼对上记录的是哪个区），不参与任何匹配（§4 红线 3） |
| 平台 | **微信 / QQ**（二选一，**可留空**）；只提供这两个选项，不给自由书写（否则会出现多种写法混在一起，没法扫一眼就看懂） |
| 区号 | 区服的编号（如 `392`），**可留空**；存**文本**而非数字（游戏里的写法未必统一，它又不参与定位，没必要为此拒收输入） |
| 校验 | 区服名称不得为空、不得含「\|」或换行；平台、区号、角色名、等级可留空，非空时同样不得含这两类字符 |
| 重复 | **同一区服只能有一条**（一个区服只有一个小号），**判重只看区服名称**（平台与区号不参与判重，填得不一样也照样算同一条）；重复时**明确提示且不写入**，不静默去重、不覆盖既有条目 |
| 编辑 | 支持增、删、改、调整顺序、整体清空 |
| 来源 | **App 内维护**；「从屏幕导入（OCR + 人工核对）」为后续能力，本版不做（理由见 M3 计划 T3-9：OCR 尚未落地、这些名字直接用于点击定位、清单是"录一次用很久"的数据） |

> 编号按**新增顺序**（FR-09 已用于前台判定）；本节放在 FR-03 之后，因为它是与跑号配置并列的配置数据。

#### FR-04 跑号主流程

用户经悬浮窗菜单发起一次执行后，程序按**预设**（服务器策略 + 好友，见 FR-07「拜访规则」）执行下列步骤。

**一次执行只处理一条**（一个账号的一次换号 + 拜访）：跑完即结束，要再来一次由用户再点一次（理由见 §1.1）。

**每一步都必须在执行动作后验证结果，验证通过才进入下一步。**

| # | 步骤 | 做什么 | 进入下一步的验证 | 未通过时 |
| --- | --- | --- | --- | --- |
| 1 | 起始确认 | — | 当前处于**启动页、服务器列表、大厅、农场或好友的农场**任一（**起点决定从第几步开始**，见下表） | 中止并提示 |
| 2 | 退出农场（**仅起点为农场 / 好友的农场时**） | 点击农场内的返回入口 → 在**返回场景确认框**里选「**返回大厅**」 | 每点一步都要看到下一个界面（确认框 → 大厅） | 停 3 次后中止 |
| 3 | 退出登录 | 三步走：在大厅点开**设置入口** → 在**设置页**点「退出登录」 → 在**确认框**点确认 | 每点一步都要看到下一个界面（设置页 → 确认框 → 启动页） | 停 3 次后中止 |
| 4 | 换区 | 点击「换区」 | 场景变为服务器列表 | 停 3 次后中止 |
| 5 | **选择区服** | 在服务器列表中查找**预设指定的区服名称**并点击 | 场景离开服务器列表、回到启动页 | 找不到即中止，不做猜测性点击 |
| 6 | 登录游戏 | 点击「开始游戏」；其间出现的活动弹窗按 FR-01 逐个关闭（可能出现 **0 个 ~ 多个**） | 场景变为大厅 | 停 3 次后中止 |
| 7 | 进入农场 | 点击「王者农场」入口 | 场景变为农场 | 停 3 次后中止 |
| 8 | 打开好友列表 | 点击农场内的好友入口 | 场景变为好友列表 | 停 3 次后中止 |
| 9 | 拜访好友 | 在列表中定位**预设指定的好友名称**并点击拜访 | 画面回到农场（**不确认是哪位好友的农场**，见 §7-1） | 停 3 次后中止 |
| 10 | 本条完成 | **停留当前界面，不做任何返回动作**：点到「拜访」即完成辅助操作 | —（无动作，无需验证） | — |

一次执行跑到区间终点即结束并提示用户。

**起点 → 起始步骤**（第 1 步命中哪个画面，就从哪一步开始）：

| 起始画面 | 从第几步开始 | 说明 |
| --- | --- | --- |
| 好友的农场 / 农场 | 第 2 步 | 需先退出农场 |
| 大厅 | 第 3 步 | 大厅没有农场退出入口 |
| 服务器列表 | 第 5 步 | 已在选服页，不必再点一次「换区」 |
| 启动页 | 第 4 步 | 统一从「换区」开始（多一次换区，但不会走错） |

> **第 3 步为什么是三步**（2026-09-19 用户确认）：游戏里退出登录要经过大厅的设置入口与一个确认弹窗，
> 中间两屏已登记为独立界面（§2.1）。**每一步之间都要验证**——否则只能盲点，而盲点无从判断"到底进没进去"。
>
> **第 2 步为什么有两步**（2026-09-19 真机取证）：农场 / 好友的农场点返回会弹出「请选择需要返回的场景」，
> 其中「返回大厅」是本流程要的；另一项「**返回稷下学院**」通往一个本版本没有定义的界面，
> 因此**不点它**——进了那里既无法验证，也不在流程的下一步范围内。
>
> **第 5 步选哪个区服**：预设指定了具体区服就用它；预设是「顺序轮换」则按**服务器清单（FR-10）的顺序取下一个**，
> 并记住上次跑到哪、下次接着往下。清单为空 = 无处可切，直接中止并提示。

> **弹窗的处理贯穿整个登录环节**：可能 0 个，也可能连续多个，逐个关闭。
> **弹窗的出现不以保证「已进入大厅」为前提**：实测（2026-09-13）弹窗可在大厅出现**之后**才弹出；因此第 6 步验证通过（场景变为大厅）之后、第 7 步动作之前，仍需按 FR-01 检查并关闭弹窗。
>
> **第 10 步之后本项即结束**，程序不要求回到某个特定界面：用户手动完成「祝福」后自行发起下一次切换小号。
> 下一次的起点可能是自己的农场或好友的农场，两者的「切换小号」操作路径一致。
>
> **大厅发起 = 农场发起流程的子集**（2026-09-13 用户确认）：起点已是**大厅**时，第 2 步不适用（大厅没有农场退出入口），
> 直接从第 3 步「退出登录」开始；此后与农场发起**完全重合**。因此「大厅 → 切换小号」只是本表从第 3 步起的部分，
> 不构成一条独立流程。

**三种执行区间**（2026-09-13 用户确认）：用户可选择流程的**终点**，从而只执行本表的一个区间；**起点仍由第 1 步确认**。

#### FR-05 跑号的中断与恢复

长链条必然会中断（验证码、网络卡顿、临时弹窗、用户切走）。中断后必须让用户能低成本接上，而不是从头再来。

| 情形 | 程序行为 |
| --- | --- |
| 任一步骤验证不通过 | 停止动作，在悬浮窗中显示**停在哪一步、什么原因**，等待用户处理 |
| 场景变为未知 | 同上；**不点击任何东西** |
| 游戏离开前台 | 立即停止动作并暂停；回到前台后不自动继续，等用户确认 |
| 用户点「继续」 | **从失败的那一步重试**，不重跑前面的步骤 |
| 用户点「停止」 | 立即停止，回到常驻守护模式 |

### 3.3 运行支撑

#### FR-07 悬浮窗与操作菜单

| 项 | 说明 |
| --- | --- |
| 展示 | **手柄 + 菜单 + 顶部状态标签**三个部件（`2026-09-28 用户口径`恢复状态标签，见「口径修订六」）；状态标签显示**当前正在进行的操作**，**有话说时常驻**、**没有话说（待命）时整体不显示**（`2026-09-30 用户口径`：待命期只藏标签、手柄保留，见「口径修订九」） |
| 外观 | 在较暗的游戏画面上必须清晰可辨（不得使用与背景同样深暗的配色） |
| 尺寸 | **紧凑到只包住内容**。悬浮窗会吞掉其覆盖范围内的触摸，铺满将导致游戏无法操作。手柄的**可见区与触摸区分离**：可见竖条 7dp（少挡视线），另有**透明触摸区**向屏内多留 16×12dp（可见 7dp 实测点不中）——**代价如实记录**：手柄实际占住屏幕边缘 23×44dp 的触摸。**触摸区不得再加宽**（2026-09-20 真机实测：扩到 48dp 会遮挡游戏操作，已回退） |
| 交互 | 收起态为一个紧凑手柄，**位置固定（右侧边缘、纵向约 1/5）且不可拖动**；单击展开菜单（**单击只展开，不执行任何操作**）；**展开后手柄不消失**；再次单击手柄、或点菜单面板之外的任何区域 → 收起。跑号中止 / 暂停时手柄**变色 + 加高 + 脉冲一次**（收起态不写字，这是唯一能提示"停在半路上"的通道） |
| 菜单 | 展开后一级为**低频维护项收进「更多」之后的高频项**：**换号 / 拜访 / 换号+拜访 / 更多 / 返回 App**（`2026-09-30 用户口径`，见「口径修订九」），另有"有流程时才出现"的进度块（顶部）与控制行（底部）。**换号**要选定具体目标时进入下一级（服务器清单，首行「**顺序轮换**」）；**拜访**进入下一级选好友（不改预设）；**换号+拜访**点整行 = 按当前预设**直接执行整条**，改「服务器策略 + 好友」用该行**行尾的「调整服务器与好友」入口**进入参数层（改的是草稿，点「**保存**」才落盘、返回即丢弃）；**更多**里放的是不启动流程的维护类动作（导入服务器 / **重新授权采集** / 暂停自动关弹窗 / 退出）。**2026-10-01 用户口径（M5 期间插入）**：菜单里要有「**一键重新授权采集**」——「更多」层**常驻**一条；根菜单另有一条**条件行**，只在**采集会话没了 / 画面久未更新 / 这次授权没被投喂**时出现（判据 `FloatingMenu.shouldOfferReauthorize`；正常跑着时**不占一行**，避免面板长高让正在点的行位移）。点它 = **App 到前台并自动拉起系统采集授权弹窗**（弹窗只能由 Activity 发起；**确认永远由用户做** ⇒ FR-08「不得由后台静默发起授权」不破）。菜单面板独立成窗，**完全在屏内**、与手柄纵向对齐。**跑号进行中**时根菜单顶部显示进度（`第 3/10 步 · 退出登录` + 当前动作 / 停止原因），底部为**流程控制行**（运行中 = 「停止」；中止 / 暂停 = 「继续｜停止」） |
| 换号 | 支持切换到**清单中指定的服务器**（清单见 FR-10），也支持**按清单顺序切到下一个** |
| 拜访 | 三个入口：**「拜访」= 跳过换号、在当前区服直接去见**（选中谁就见谁，不要求预设）；**「换号+拜访」= 按预设先换号、再去见预设好友**（要求预设里**好友非空**）；**「换号」= 只换号、不拜访** |
| 提示 | **一律走顶部状态标签**（`2026-09-29 用户口径`：底部浮窗提示已整体移除，见「口径修订七」）；失败仍走菜单内的**原因条**（保持展开、不静默）。跑号**中止 / 暂停 / 完成**由标签**常驻**显示（原因在菜单进度块里），读屏播报由标签在结局**变化**时播一次 |
| 拖动 | **只有顶部状态标签可拖动**（`2026-09-28 用户口径`，见「口径修订六」；手柄与菜单仍不可拖动）——标签位置以**屏幕比例**落盘，拖到哪就一直在哪 |
| 贴边 | 手柄**固定在右侧边缘、纵向约 1/5**（可见窄竖条 7dp + 向屏内的透明触摸区）；**位置是布局常量、不持久化**——理由：只有用户能改的东西才该落盘（曾持久化手柄位置，结果旧值一直压住新默认值） |
| 收起时机 | 操作成功结束后立即收起；失败时保持展开并显示原因 |
| 可见性 | **仅游戏在前台时可见**，非前台时完全消失（既不可见也不占触摸），回到前台后以收起态恢复 |
| 不干扰 | 悬浮窗的可见性、位置、展开状态**不得改变识别结果** |

>   命中条数与落点都进日志，事后可取证。
>
> **口径修订十一（2026-10-01 用户确认）**：**好友列表改为「当前屏先找一次，命中即点；找不到再回顶慢慢找」**
> —— 推翻落地「口径修订十」时那条"**命中前必须先回到列表顶部**"（FR-04 硬性要求 #4 的好友附加条）。
> 用户原话："**每次都滑到顶再找有点费事，改为在当前屏先找一次，找不到再滑到顶慢慢找，如何？**"
> - **流程**：进好友列表 ⇒ ① **当前屏先读一次**：命中 ⇒ **直接点拜访（不回顶）**；
>   ② 当前屏没有 ⇒ 回顶（除非已知自己在顶部：换号流程刚登录 / 与上次学到的"顶部那一屏"一致 /
>   回顶时画面不再动）⇒ 再自上而下逐屏找，上限仍 **5 屏**；
> - **判据一个字没动**：命中仍是"取括号内备注 + 全等"（红线 3）；**同一屏上**多个完全同名时仍取
>   **最上面**那一行（`NameLocating.locateFriend`，只在同屏比 y）；
> - ⚠ **代价如实记录**：放弃的是"**整个列表**的最上面"这一点 —— 若同一备注在**更上面那一屏**还有小号，
>   会点在**当前屏**那一行（用户此前对"同名可能点错人"已知并接受，本次是主动拿它换速度）；
> - **为什么**：每次白滑 1~2 秒（拖动 + 稳定等待 + 整屏读数），在"只拜访"这条常用路径上体感明显。
>
> **口径修订十二（2026-10-01 用户确认）**：**第 9 步在「当前屏没有」之后改为走「搜索式查找」**，
> 不再默认滑屏找人。用户口径："**先看当前屏；没有就搜索**"（起因：滑屏找好友常超过单步预算被中止、
> 列表长时还有"跳屏漏人"的风险，而游戏自带搜索一次就能列出所有同名小号）。
> - **流程**：进好友列表 ⇒ ① **当前屏先读一次**（沿用「口径修订十一」：命中即点，不回顶）；
>   ② 当前屏没有 ⇒ 按用户校正过的顺序走五小步 —— **点「搜好友」→ 点搜索框 → 填目标昵称（原生写入）
>   → 提交 / 收输入法 → 点「搜索」** ⇒ **结果页仍是普通好友行**（行尾还是「拜访」图标）⇒
>   交给**同一套**名称定位判定；
> - **判据一个字没动**（红线 3 不变）：命中仍是"取**括号内备注** + **全等**"，结果页里多个**完全同名**
>   仍取**最上面**那一个；
> - **搜索之后不再滑屏**：搜索都找不到 ⇒ **如实停下并提示**，不"再滑滑看"；写入没进搜索框时
>   **最多重写 2 次**，用完即停下（旧现象"点搜索提示请输入文本 → 又回去点输入框 → 无限重复到超时"已消除）；
> - **单步预算**：这一步单独放宽到 **25 秒**（搜索链一次半 + 结果页等待 + 点拜访的余量），
>   其余步骤仍是 15 秒（第 3 / 6 步另有各自更宽的预算）；
> - **兜底（不回归）**：三个搜索锚点**未标定**、或写文字失败 ⇒ 自动**退回原来的滑屏找**
>   —— FR-04 硬性要求 #4 那套逐屏扫描**保留**（第 5 步「选服」也仍在用它，区服列表没有搜索功能）；
> - **新增标定项 3 个**：`搜好友（底部入口）` / `搜索框` / `搜索按钮`（见 §2.1 与标定清单）。
>
> **口径修订八（2026-09-29 用户确认）**：① 标签文案**再精简**（用户原话："**去除「第x步」、步骤序号这种
> 不重要的信息，关键是目前在做什么**"）⇒ 跑号时只显示**这一步做什么**（`退出登录` / `选择区服`），不再带步号；
> 上限从 12 字收到 **8 字**（`FloatingLabelText.MAX_CHARS`）。步号与"还剩几步"展开菜单即可看到。
> ② **移除底部浮窗提示**（用户原话："**既然顶部增加了悬浮窗,那么底部的toast是不是可以去除了?**"）

> （菜单收起 + 标签立刻显示正在做的事已足够）；跑号**中止 / 暂停 / 完成**由标签**常驻**显示
> （FR-05「不静默」仍成立：标签 + 手柄告警色 + 菜单原因条 / 进度块）；**读屏播报**改由标签在结局
> **变化**时 `announceForAccessibility` 一次（T4-5 的口径不变：不能只对看得见屏幕的人说）。
> 随之下线：`FloatingNotifierTest`、`PatrolRequestSignal.Request.briefText()`（无调用方，不留死代码）。

#### FR-08 后台运行

| 项 | 说明 |
| --- | --- |
| 常驻 | 识别与跑号必须在后台持续运行，不依赖前台界面存活；切后台、熄屏不被系统中止 |
| 通知 | 服务在系统通知中可见，用户能据此确认程序正在运行 |
| 授权 | 关键授权必须由用户在前台界面中主动确认，不得由后台静默发起 |
| 提示 | 授权状态与运行状态必须展示，避免出现「什么都不发生」的沉默失败 |

#### FR-09 前台判定

| 项 | 说明 |
| --- | --- |
| 判定对象 | 目标应用是否位于前台 |
| 独立信号 | 必须是**独立判定**，不能以「没有识别到任何标志」代替——加载页、黑屏同样识别不到标志，二者是两件事 |
| 判定失败 | 无法取得前台信息时，一律**按非前台处理**：隐藏悬浮窗、停止一切操作、中止跑号并提示。宁可停住，不可乱点 |
| 生效延迟 | 前台状态变化后 2 秒内生效 |
| 作用 | 非前台时不点击；非前台时中止跑号；非前台期间不消耗 §2.2 的连续计数（否则重新登录时跳转外部授权会被凑满「连续未命中」而误判失败） |
| 会话区分 | 「用户切到别的应用」只隐藏悬浮窗、停止操作，回来自动恢复；「采集会话终止」（用户主动停止、锁屏、进程被回收）才停止循环并引导重新授权。二者混淆会变成「切走一次就要求重新授权」 |

> **口径修订一（2026-10-01，用户报障后确认）**：「判定失败 ⇒ 一律按非前台处理」这条**加一道确认** ——
> 但**只加在"用户可见的后果"上，安全侧不加任何延迟**。
> 起因：用户报"**游戏在前台，却提示不在前台**"；真机实录 vivo 桌面（`com.bbk.launcher2`）**短暂抢走
> 活动窗口 2.70 / 2.99 秒**，而游戏窗口一直在屏上 ⇒ 那两秒里"悬浮窗被摘 + 跑号被暂停（要用户手动点
> 「继续」）"全是白挨的 ✗。
> - **真离开**（游戏窗口**不在屏上**，或一个都没有）⇒ 照旧**立刻**生效（本条原意不变）；
> - **只是焦点被抢**（游戏窗口**还在屏上且可见**）⇒ **先闸住一切点击**（安全侧零延迟、一枪不打），
>   **等下一次复核确认**；持续 ≥ **3.5 秒**才认下"不在前台"（暂停 + 摘悬浮窗）。
> - 「生效延迟 2 秒」一条**不变**（周期复核仍是 1.5 秒一轮：这里多出来的是"确认"，不是"检测"）。
> - 📌 复核日志必须带**判据三件套**：**活动窗口包名 / 游戏窗口几个（可见吗）/ 本屏窗口总数**
>   —— 只有"事件判 X 不在前台"这半句，排障时定不了论。

## 4. 关键约束

**能点什么**

1. FR-01 活动弹窗自动关闭，一类异常处理。
2. FR-02 新手引导 / 新手大厅自动关闭，**同一类异常处理**（复用同一套闭环，仅审计来源不同）。
3. §3.2 跑号主流程中明确定义的步骤。
4. 用户通过悬浮窗菜单发起的操作。

**不能点什么**

| # | 约束 |
| --- | --- |
| 1 | 游戏不在前台时，**一律不点击** |
| 2 | 状态为未知时，**一律不点击**——界面不明时的「试探性点击」是最危险的行为 |
| 3 | 不点击跑号流程步骤之外的任何按钮（不领取奖励、不购买、不消费、不参与任何玩法） |
| 4 | 服务器与好友必须按配置指定的名称定位；**宁可停下也不用猜测的位置** |
| 5 | 常驻守护模式下，除 FR-01 外不产生任何点击 |
| 6 | 跑号与常驻守护的动作不得同时下发 |

**为什么第 4 条特别重要**：切换区服与拜访好友都涉及「在一堆外形高度一致的目标里挑一个」。挑错的代价不可逆（进错区服、打扰错好友），因此定位必须由配置给定的名称唯一确定；名称匹配不唯一或找不到时，正确做法是停下，而不是挑一个最像的。**唯一例外**见「口径修订十」：好友列表里多个**完全同名**（同一个人有多个小号、共用一个备注）⇒ 取**最上面**那一个 —— 那**不是**"挑一个最像的"（判定仍是"取括号内备注 + 全等"，完全同名才适用）。

## 5. 识别能力要求

识别是本项目一切动作的前提。本节不规定怎么做，只规定结果必须满足什么。

| # | 要求 | 说明 |
| --- | --- | --- |
| 1 | 判定可审计 | 每次判定都要给出：命中了哪个标志、位置在哪、置信度多少、同一画面里最强的竞争位置是什么。用于事后核对「这次点击有没有点错」 |
| 2 | 不得只靠「分数最高」下结论 | 存在多处高分，或最高分与次高分差距过小时，判为**不可信**并按未识别处理 |
| 3 | 抗干扰 | 下列三种情况下不得误判：① 目标上叠了半透明遮罩；② 目标所在区域背景在动；③ 同一画面有多个外观相近的文字、图标或按钮而只有一个位置是目标 |
| 4 | 可复现 | 同一批画面数据、同一套参数，重复执行必须得到相同结果；参数调整后能对既有画面整体重跑并比对 |
| 5 | 设备无关 | 识别能力必须在**目标设备上自行建立**，不得硬编码任何与开发设备绑定的尺寸、密度、位置或阈值；更换设备后重建，指标不得下降 |
| 6 | 不受悬浮窗影响 | 悬浮窗开启或关闭、位置不同、展开或收起，同一画面的识别结果必须一致 |

**验收误报率时的口径**：负样本不少于 60 个；「零误报」必须以上界表述（n 个样本 0 次误报 → 真实误报率上界为 `1 − 0.05^(1/n)`）；三类干扰分别统计，不得合并成一个总通过率。样本不足时不得声称「零误报」。

> 第 3 类干扰是本项目的重点考点：「选择区服」与「拜访好友」都要在一堆外形相似的目标里挑一个，正是干扰最严重的场景。

## 6. 非功能需求

| 编号 | 要求 | 验收要点 |
| --- | --- | --- |
| NFR-01 | 单帧处理耗时 < 20ms | 真机连续 100 帧统计，P95 小于 20ms |
| NFR-02 | 检测间隔自适应：**需要响应时 ≤ 0.2s**（未达预期 / 画面变化 / 刚转移），**确实稳定时 ≤ 1s**。间隔指**两轮之间的休息时间**（单轮处理耗时不计入） | 稳定挂机时资源占用显著低于固定短间隔轮询；快档下「预期出现 → 确认」≤ 0.5s，与人工「看到界面 → 点击」的 200 ~ 400ms 同量级（且受 FR-04 硬性 #8「相邻点击 ≥ 300ms」约束） |
| NFR-03 | 安装包 ≤ 25MB，兼容 **Android 14 及以上**（口径修订：2026-10-01 用户确认，原写 9.0+） | 发布包实测；目标设备（Android 16）与本平台最低版本（Android 14）上均能完成授权、识别、悬浮窗可见 |
| NFR-04 | 连续运行 30 分钟无崩溃，内存不持续增长 | 真机长跑观察内存趋势 |
| NFR-05 | 不得点击到非预期位置 | 日志核对：每次点击都有对应的识别记录与判据 |
| NFR-06 | 两次点击间隔不低于 300ms | 日志核对相邻点击的时间戳 |

> NFR-05 是最重要的一条：误点击的代价远高于漏识别。漏识别只是流程停住，用户可以补一步；误点击可能进错区服、打扰错好友，或触发游戏内不可逆操作。§4 的全部约束与 §5 的可审计要求都是为这一条服务。

## 附：实现建议与维护方式
