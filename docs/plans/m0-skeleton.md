- **做**：授权状态采集与引导、前台独立判定、后台常驻服务与通知、悬浮窗壳（仅前台可见、触摸穿透、紧凑、收起态手柄）。
- **不做**：画面识别、任何点击（本里程碑全程零点击）、巡查逻辑、悬浮窗完整交互（拖动 / 贴边 / 菜单，M3 再做）。

## 任务卡

### T0-1 决策前置：落地 ADR-001 / 002 / 004 / 005

- 目标：确定采集、注入、悬浮窗、前台判定的技术途径
- 验收：四条 ADR 状态为"接受"；`architecture.md` 开放决策表同步更新
- 证据：ADR 文件链接
- 备注：先于 T0-2 完成；ADR-002 需同时确定"间隔 ≥300ms 的唯一实现点"

### T0-2 授权流

- 目标：用户可在前台界面看到各关键授权状态，并一键前往授予
- 验收：A1
- 证据：真机截图 + 授权状态矩阵（全部已授 / 缺一项 / 全缺）
- 备注：关键授权 = ①无障碍服务 ②屏幕采集（会话制）③通知（Android 13+）；采集会话的创建与维持由 T0-4 服务壳接入，本任务只做状态展示与授权引导

### T0-3 前台判定

- 目标：独立的"是否前台"信号，2 秒内生效，判定失败按非前台
- 验收：A2
- 证据：前后台切换时序日志（含时间戳）
- 备注：信号源为无障碍服务窗口信息，双来源——窗口事件即时评估 + 1.5s 周期主动复核兜底；判定规则：活动窗口包名 == 目标应用包名，其余（含查询失败、服务不可用）一律非前台；目标包名 M0 以常量给定（M3 配置化）；状态每次变化输出日志（即证据本体）

### T0-4 服务壳

- 目标：常驻服务 + 系统通知 + 运行状态展示
- 验收：A3
- 证据：切后台 / 熄屏观察记录
- 备注：范围界定——只做常驻守护服务（前台服务，类型 specialUse：Android 14+ 要求前台服务声明类型，守护用途取兜底类型）、系统通知与应用内运行状态展示；真实采集会话（mediaProjection 类型服务 + 虚拟显示）顺延至采集层任务——T0-2 备注中「由 T0-4 服务壳接入」的约定随之顺延（采集会话依赖识别层的真实采集需求，届时按 ADR-001 顺序：先启动对应类型前台服务、再创建会话）；服务由用户在前台界面主动启动/停止（系统禁止后台静默启动前台服务，与「关键授权必须前台确认」语义一致）；「不被中止」的观察方式：切后台、熄屏各保持数分钟，以系统服务查询确认存活（不依赖界面）

### T0-5 悬浮窗壳

- 目标：可见性规则 + 触摸穿透 + 紧凑收起态手柄
- 验收：A4、A5
- 证据：真机手测记录（含"非前台完全消失"与"穿透可操作"两条）
