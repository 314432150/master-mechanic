## 任务卡（草案，口径确认后逐张写实）

### T4-1 执行器骨架 + 步骤状态机（纯逻辑）
- 目标：把 FR-04 的表变成**可单测的状态机** —— 步骤编号、起点判定、区间（只换号 / 换号 + 拜访）、
  "验证通过 → 下一步"/"不过 → 停并给原因"、单步重试上限 3 次、相邻点击 ≥300ms。
- 验收：纯逻辑单测覆盖**三条区间 × 各起点**；失败时停在正确步骤并给出原因。

### T4-2 场景识别接入（起点判定 + 每步验证）
- 目标：复用 M1/M2 的识别能力，提供"当前场景是哪一个"的查询（启动页 / 服务器列表 / 大厅 / 农场 / 好友的农场 / 未知）。
- 验收：单测 + 真机逐场景核对（用户操作）。

### T4-3 名称定位（区服 / 好友）
- 目标：在服务器列表 / 好友列表里按**名称精确定位**可点位置；**不唯一或找不到 = 未找到**（绝不挑"最像的"）。
- 验收：单测（含重名、滚动查找次数上限）+ 真机核对。

### T4-4 点击注入（受控出口）
- 目标：把"点某处"做成一个受控出口：节流 ≥300ms、跑号期间暂停其它自动动作、**游戏离开前台立即停**。
- 验收：单测（节流 / 暂停 / 恢复）+ 真机（用户操作）。

### T4-5 悬浮窗进度与中断恢复（FR-05 / FR-06）
- 目标：显示"当前第几步 / 停在哪个账号的哪一步、什么原因"；「停止」真的能停；「继续」从失败那步重试。
- 验收：真机核对。

## 验收清单（草案）

- [ ] 三条区间都能跑通（真机，用户操作）
- [ ] 每步执行后都有验证，验证不过即停（**不连续盲点**）
- [ ] 名称定位不唯一 / 找不到 → 停并提示（**不做猜测性点击**）
- [ ] 相邻点击 ≥300ms；游戏离开前台 → 立即暂停
- [ ] 中止后**不自动重试**整条流程，只能由用户「继续」或「跳过」
- [ ] 跑号期间不产生任何"非预期位置"的点击（NFR-05：日志里每次点击都能对上一条识别记录）
