> **临时短期需求**（2026-10-21 用户提出，2026-10-21 拍板口径）：活动结束即整体移除（见文末「移除清单」）。

> 分支：`temp/badge-share-1021`（自 main = `80464e8`，M5 已合并）。

## 背景

王者荣耀「收集高分立牌换皮肤」活动（小王生日会，2026-10）：

- 同一账号在不同区服建有角色（下称**小号**；「十几个服务器 = 十几个子账号」）；
- 登录后在活动页领「登录游戏」任务的立牌，每张立牌有**分享码**与**价值分数**；
- 立牌**每日 0 点由游戏清空**（「我的立牌」页原文），分享码当日有效；
- 目标：自动换服收集各小号当日立牌分享码 → 按分数倒序在悬浮窗「立牌池」展示 → 用户手动复制使用。

## 范围（2026-10-21 用户拍板）

| # | 拍板 | 影响 |
| --- | --- | --- |
| 1 | 十几个服务器 = 同账号不同区服的**子账号**，流程是**换区切子账号**，不是官方「转区」服务 | 复用现有换号切服流程（FR-04 换号段），无转区风险 |
| 2 | 立牌数据获取 = **OCR 读屏**（读分享弹框明文），不读剪贴板 | Android 10+ 后台读剪贴板被系统禁止；弹框上 `【…】价值…分` 明文可见 ⇒ 直接文字识别。**不点「复制分享码」、不清剪贴板** |
| 3 | **不做**自动「提交领积分」 | 只收集 + 展示 + 复制；使用端用户手动 |
| 4 | **不做**「每日完成一场对局」那张立牌 | 只领「登录游戏」任务的立牌（「获取立牌」弹框里另一条永远不碰） |

## 验收（先验收后实现）

- **FR-T1 换号取立牌主链**：悬浮窗菜单「换号取立牌」→ 按服务器清单顺序换区登录进大厅 → 活动页
  （每日首次进入的自动提交立牌过程**不点「跳过」**，等待其自然结束到活动中心）→
  今日未获取 ⇒「获取立牌」→ 领取「登录游戏」立牌（已获取 ⇒ 跳过，直接下一步）→
  「分享立牌」进复制分享弹框 → OCR 逐块读出**立牌名 / 分享码 / 分数** → 记录 →
  「切换」进「我的立牌」→ 逐张「分享」再读 → 关闭 → 返回大厅 → 下一个区服，直至清单跑完。
- **FR-T2 已领取容错**：同一天同一区服第二次跑到「领取」，识别到「已领取」→ 不报错、不重领，继续分享步；
  当日该区服**已完成过收集**（收集完成标记）→ 整号跳过，不进活动。
- **FR-T3 立牌池展示**：悬浮窗「立牌池」入口 → 当日记录按分数**倒序**；默认 top 3 +「更多」展开全部；
  每行 = 区服名 + 分数 +「复制」（分享码写入剪贴板）+ 回执提示。
- **FR-T4 跨日清空**：记录带日期；**读取时**日期非当天 → 清空（U8 同款：LocalDate 比较，不做定时任务）。
  与游戏「立牌每日 0 点清空」同步失效。
- **FR-T5 失败停下**：任一步识别不到 / 不唯一 / 不可信 → 停下并提示原因，**不盲跳下一个区服**
  （红线 3/5/7 全程适用；解析不出分享码按未识别处理）。
- **FR-T6 活动结束移除**：本分支整支可删（见「移除清单」），主干不留依赖。

## 红线适配

| 红线 | 落点 |
| --- | --- |
| 1 零点击 | 状态未知 / 游戏不在前台 → 流程步不动手（沿用 ClickGate） |
| 2 点击来源 | 本流程的点击属「用户经悬浮窗菜单发起的操作」（点「换号取立牌」）；仅流程步骤内点击 |
| 3 名称唯一 | 区服定位沿用 `NameLocating` 全等 + 唯一口径；分享码解析出的字段不参与点击定位 |
| 4 零硬编码 | 活动页各步锚点全部走自标定产物；解析器只吃 OCR 文本，不碰坐标 |
| 5 动作后验证 | 每步验证下一步的画面状态再动手；「领取」的「已领取」态是**合法验证结果**（继续而非报错） |
| 6 点击节流 | 走统一 `ClickForwarder`（≥300ms） |
| 7 不可信按未识别 | OCR 文本解析不出 / 分数缺失 / 码缺失 → 停下报原因，不猜、不带残缺记录继续 |

## 实现口径

- **模块**：`app/src/main/java/com/example/mastermechanic/badge/`（独立包，移除时整删）
  - `ShareCodeParser`：分享弹框 OCR 文本 → `(立牌名, 分享码, 分数)`；纯函数。容错仅限
    空白 / 全角 / 小写码归一；**其余一律解析失败**（红线 7）。
  - `BadgeRecord` + `BadgeCodec`：行式存盘（`mm-badge` v1）：
    `record=<区服名>|<立牌名>|<分享码>|<分数>|<日期>`、`collected=<区服名>|<日期>`（收集完成标记）。
    解析严格（ServerListCodec 同款口径：带行号报错、不静默兼容）。
  - `BadgeStore`：`filesDir/badge/records.txt`；**读时按今天过滤**（FR-T4）；
    upsert 按分享码去重；`markCollected` / `hasCollected`（FR-T2 跳过判据）。写盘 tmp+rename。
  - `BadgePoolView`：展示纯逻辑（倒序 / top 3 / 展开 / 更多行可见性），JVM 可测。
- **换号段**：复用 `PatrolFlow` 换号区间（到大厅）；活动支线由 badge 流程接手（标定批 1 后实现）。
- **小号名 = 当前区服名**（切服上下文已有），不读游戏昵称。
- **悬浮窗**：一级加「立牌池」行（进 `Level.BADGE_POOL`）；「换号取立牌」随流程切片接入。
  立牌池页 = 面包屑 + 行列表（`boundedScroll`）+「更多/收起」+ 行尾「复制」。
- **数据字段**（用户口径「记录分享码、分数、名字」）：区服名、立牌名（如「墨子顶级立牌」）、
  分享码（如 `1M09G2`）、分数（如 `877`）、记录日期。

## 接入跑号运行时（Slice 3 设计，2026-10-21）

读完运行时（`PatrolRequestSignal` → `PatrolRequestConsumer` → `PatrolSession` → `PatrolFlow` /
`PatrolAnchors` / `PatrolScenes` → `PatrolRunner` → `CaptureService.stepPatrol` → `ClickDispatch`）后定：
**并列任务 + 独立状态机**，不扩 `PatrolFlow.Step`。

### 为什么不是"往 PatrolFlow 里加步骤"

1. `PatrolAnchors.Action(state, anchor, expect)` 是**静态映射**，装不下立牌的三处条件分支
   （空槽判领取 / 今日已获取 / 已领取）；
2. `PatrolFlow.Range` 是**单次线性区间**，装不下"换号 → 支线 → 换下一个区服"的循环；
3. FR-T6 要求整支可删：混进主流程枚举，移除时就得回滚主流程（回归风险全落在巡查上）。

⇒ 立牌自己一套（都在 `badge/` 包内），**只借用**主流程已验收的组件。

### 借用（不复制）

| 现有组件 | 立牌怎么用 |
| --- | --- |
| `PatrolFlow` + `PatrolRunner`（`Range.SWITCH_ONLY`） | 任务第 1 阶段就是换号段第 3~6 步（退出登录 → 换区 → 选服 → 登录进大厅），连同第 5 步的名称定位 / 跨屏扫描 / 单步预算 / 口径 A 一起复用 |
| `PatrolScenes.read` / `startStates` | 起点判定与换号段验证目标完全一致 |
| `AnchorLocator` / `ClickDispatch` / `ClickGate` | 锚点定位与点击下发（红线 1/6 的唯一实现点，不另开旁路） |
| `PatrolDrivenExpectedSignals.watch` | 每轮把立牌的期望集合喂进**同一个**识别循环（识别只有一份） |

### 新增（`badge/` 内，可整删）

| 文件 | 职责 |
| --- | --- |
| `BadgeFlow` | 立牌支线纯状态机：步骤 / 分支 / 超时 / 失败停下（JVM 可测） |
| `BadgeScenes` | 步骤 →（状态 / 锚点 / 期望）+ 每轮期望集合 + 分支判据（纯逻辑） |
| `BadgeRunner` | 每轮编排：等 / 点 / 进下一步 / 停（与 `PatrolRunner` 同形、同样不点不识别） |
| `BadgeSession` | 进行中的立牌任务（阶段 + 目标区服 + 已读卡位置 + 代次），与 `PatrolSession` 互斥 |
| `BadgeTask` | 跨区服循环：清单顺序 + 今日已收集跳过（FR-T2）+ 收尾标记 |

### 接线点（只有四处）

1. **菜单**：`FloatingMenu` 根菜单加「换号取立牌」→ 新 `Kind.BADGE_COLLECT` →

- **展开行文案叫「展开全部 / 收起」而不是「更多」**：入口已在菜单「更多」层下，再放一个「更多」会分不清指哪层。
- **临时状态不进 glossary / requirements §2.1**（2026-10-21）：`UiState` 新增四态只认本文件口径
  （`ACTIVITY_CENTER` / `BADGE_CLAIM` / `BADGE_MY` / `BADGE_SHARE`）—— 活动性需求不改主需求，活动结束随分支移除。
- **标志（marker）一律框标题文字，别框右上角白 X**：立牌弹框的关闭控件与 FR-01 活动弹窗的关闭控件**同形（白 X）**
  —— 拿 X 当标志既分不出是哪个弹框，又有被 FR-01 自动关弹窗误点的风险（详见 `BadgeAnchors` 文件头）。
  X 只作为锚点用途框。
- **锚点契约**：`badge/BadgeAnchors.kt`（锚点名 = 用途名；`PatrolAnchors.purposesFor` 合并其用途表、
  `nonLocatableAnchors` 并入分享码文本区）。「领取」「分享」是**同模板多实例**，运行时按行 / 卡归属
  消歧（Slice 3；红线 3「不选最像的」同源适用）。
- **未见过屏的控件一律不声明**：「继续」、活动介绍「跳过」、第二个「返回」在哪个屏上还没证据
  ⇒ 不进契约；标定走到那几屏时补（下面清单的「待发现项」）。「切换」2026-10-21 真机确认在
  **复制分享弹框**上（点它才进「我的立牌」）。
- **数据获取口径修正（2026-10-21 真机 + 用户拍板）**：复制分享弹框的立牌信息**分三块**（分数 /
  立牌名称 / 分享码）⇒ Slice 3 逐块 OCR 取值组装记录（`ShareCodeParser.parseScore / parseName /
  parseCode`；空白按 OCR 噪声粘回，非空白分隔的多值按不可信）。剪贴板里 `【…】价值…分` 那种
  整行格式**不考虑** —— 那是点「复制分享码」才写进剪贴板的文本，本流程不点那颗按钮。
- **每日首次打开活动的自动提交过程：不点「跳过」，等待自然结束**（2026-10-21 用户拍板）：
  红线 2 口径（流程外不产生点击）；等待有超时，超时按 FR-T5 停下报原因，不盲点。
- **领取分支（2026-10-21 用户口径 + 三态对照帧钉死）**：今日**还没获取过**立牌 ⇒ 点「获取立牌」
  走领取；今日**已获取** ⇒ 直接点「分享立牌」。**判据只用一个：蛋糕上方圆形「+」空槽的模板存在性**
  （2026-10-21 用户拍板：空槽与「今日总分」二选一，留空槽 —— 二值判定、不碰 OCR）。
  - 空槽**在** ⇒ 未获取（点「获取立牌」）；空槽**不在** ⇒ 已获取（直接「分享立牌」）。
    三态对照帧已证：领到后槽里换成立牌 + 分数，「+」消失。
  - 为什么不选「今日总分」：区域只能把「图标 + 分数」一起框（居中排列），图标可能被 OCR 成怪字符；
    空槽没有这个问题。
  - **不用「提交领积分」的灰/亮**：要区分"灰 / 亮"两套模板，且已提交后按钮**消失**（第三态），
    比空槽多一层不确定。
  - **不能用「获取立牌」按钮判领取**：已获取未提交时它**仍然在**（三帧已证），它消失只代表已提交。
  - 风险与兜底：空槽模板若因活动换皮失效，未命中会被当成"已获取" ⇒ 分享无立牌 ⇒ 按 FR-T5 停下报原因
    （停止 ≠ 错动作）；届时回退「今日总分」只需加回一个区域用途。
