## 任务卡

### T2-1 预期集合驱动落地（识别层口径切换）——**已完成（2026-09-13）**

- 目标：`ActiveSignalSelector.select(state, round)` → `select(expected)`；空集合 = 不搜；「未知」= 预期集合内连续 3 次未命中
- 验收：M1 演练路径改为显式声明全集后行为不变（固定批次 `set-20260912-03` 判定零漂移）；单测覆盖「空集合 / 子集 / 全集」三态
- 证据：单测 + 固定批次回放报告
- 备注：预期集合的需求依据为 FR-04「进入下一步的验证」列（步 1 = {农场, 好友的农场, 大厅}；步 6 = {大厅} ∪ {活动弹窗}）
- **实现（2026-09-13，本轮）**：
  - 新增 `decision/ExpectedSignals.kt`：期望集合来源接口（`expected(known)` 取本轮信号名、`onRound(hits)` 供阶段推进，
    默认空实现）；三种实现——`ALL`（**显式声明全集** = 演练 / 回归口径）、`NONE`（不搜）、`FixedExpectedSignals`（固定集合），
    以及 **`PopupPhaseExpectedSignals`**（FR-01 弹窗阶段源，由状态—信号规则构造）。
  - `ActiveSignalSelector` 收敛为「期望集合 ∩ 已标定信号名」：**剔除未标定的期望名**（不能把"没有的能力"记成搜索量）、
    **空集原样返回**；删除 `fromRules` 与「按状态自动选子集 / 状态未知即全扫 / 补扫 / 周期兜底」全部历史路径。
  - `RecognitionLoop`：构造参数 `selector` → `expectedSignals`（默认 `ALL`）；**空集合 = 不搜**（不产生判定记录与
    耗时样本，对状态机如同不存在）；`RoundResult.searched` 由可空集合改为**非空集合**（空集 = 不搜，原 `null` = 全扫语义取消）；
    前台轮末调用 `onRound(hits)`——**用本轮原始命中推进阶段，不等滞回结论**（等 2 轮会让刚弹出的弹窗在本轮与下一轮都搜不到）。
  - **阶段口径（用户拍板，见「已确认口径」第 6 条）**：守护待命只搜「启动页」；命中启动页 → 弹窗期
    {启动页 ∪ 选择服务器 ∪ 活动弹窗（含全部样式记录）∪ 大厅}；命中大厅 → 收回待命。`CalibrationData.toLoop()`
    默认注入该源；演练 / 离线回归走 `toLoop(ExpectedSignals.ALL)`。
  - 运行日志：新增 `本轮搜索集合变化: 「…」 /（本轮不搜）`（集合一变就记一行，真机可直接读出阶段推进）；
    统计行由「子集 / 全扫」改为「**单信号 N 轮 / 多信号 N 轮 / 不搜 N 轮**」。
- **验证（2026-09-13）**：全量单测 231 例 0 失败（30 套件）+ `assembleDebug` 通过——新增 `PopupPhaseExpectedSignalsTest` 8 例、
  重写 `ActiveSignalSelectorTest`（选择规则 4 例 + 循环集成 6 例）；固定批次 `set-20260912-03` 回放报表重跑与归档
  `recognition/reports/report-20260912-t16e-batch01.md` **逐行一致（Compare-Object 无差异）**。
- **证据边界（如实记录）**：回放报表走的是检测层（`SignalDetector` 直接出判定），**不经过 `RecognitionLoop`**，
  因此「零漂移」在报表层只能证明检测 / 映射零改动；"显式全集 = 每轮全搜 = 改动前的全扫轮" 由循环层单测
  `fullSetSearchesEveryCalibratedSignal` / `fullSetExpectationKeepsOldBehaviour` 承担。改动前默认口径是
  「按状态子集 + 未知全扫」，与全集的轮次差异（旧口径下当前状态已知时换界面要等 3 轮未知才认）**如实保留**，
  不宣称"与旧默认行为完全一致"。

### T2-2 FR-01 标定补充（T1-8b 收窄版，前置）

- 目标：标定 `popup_close` 多样式 +「关闭 / 跳过」文字标志 —— 活动弹窗的关闭控件位置与样式随活动变化，需逐样式覆盖
- 验收：逐信号真机复演命中；产物同源灰度裁剪（红线 4）
- 证据：产物 + 复演日志（`docs/verification/`）
- 待标定样式（离线核对既有样本，`set-20260912-02` idx10/11/12/57/58/59）：① 限时点券·宝箱版 ② 限时点券·多头像版 ③ 万象棋·紫白卡片版——三种样式的关闭入口均为内容带右上角「×」与右下角「今日不再弹出」；设备现有产物 `popup_close` 窗口落在**右下角**（`0.653472,0.567866,0.957639,0.591540`，即「今日不再弹出」一带），右上角 × 尚未覆盖
- 捷径：停在**任一未标定界面**会走未知态全扫 → 约 90 秒补齐全部信号窗口；**须在 T2-1 切换前使用**
  （切成 `select(expected)` 后不再有「未标定即全扫」这条路径）——**T2-1 已于 2026-09-13 落地，该捷径关闭**；
  用户在切换前已完成标定（产物 `ACTIVITY_POPUP` 现挂 4 条记录：`popup_close` = 右下「今日不再弹出」，
  `popup_close2/3/4` = 右上角「×」的三种样式，三窗口几乎重合）
- **写入方式：方案 A 同状态多条记录（2026-09-13 用户拍板）**——框选写入按归属状态默认名**追加**，
  重名自动追加序号（`popup_close` → `popup_close2` → …），各条记录保有自己的搜索窗口与模板；
  同一状态的多条记录合成一条状态规则（任一命中即该状态命中，§2.1）。
  理由：一条记录只对应一个元素 / 一个点击位置（T2-3 锚点），且 T1-13b 已证明窗口面积是成本主杠杆，
  合并成一条只能把窗口扩到覆盖两处。修正误标 = 产物清单中删除该条后重标。
  备选 B（同名多模板、窗口取并集）**不采纳**：覆盖语义丢失、窗口膨胀。
- **前置缺口已解决（2026-09-13 本轮实现）**：原写入路径固定「信号名 = 状态默认名 + 同名整体覆盖」→
  新增 `CalibrationSignals.nextName(current, base)`（纯逻辑，默认名空闲即用、否则取序号最小的未占用名）；
  `CalibrationScreen.writeSignalFromSelection` 改为追加写入；文案 `calibration_signal_added`
  「已新增信号：…（该状态现有 N 条记录）」取代原「已写入 / 已覆盖」两条。
  产物格式与识别侧**未改动**（`state=` 行多信号名、`SignalStateMapping` 多对一、`ActiveSignalSelector`
  子集选择均原生支持多条记录）；单测 5 例（命名 4 + 同状态多记录规则/窗口独立性 1），全量单测 + `assembleDebug` 通过。
- 备注：新手引导 / 新手大厅标志**不再标定**（FR-02 已移除）；`samples-index.md` 中那两批样本仅作历史留存
- 备注（性能影响）：同状态记录数为 N 时，「搜该状态」一轮成本 ≈ N 条信号的耗时之和（真机 `popup_close`
  单条约 69ms，3 条约 200ms）→ M5 需连同窗口收紧一并评估（真实运行时该状态多数轮只命中 1 条，但匹配成本按全部条目计）。
- **待真机执行**（用户操作、我只读取证）：① 逐样式停稳后框选写入（记录自动落 `popup_close2`…）——**已完成**；
  ② 停在弹窗界面复演，核对日志「本轮搜索集合变化 / 本轮搜索」与命中信号名（T2-1 后口径为期望集合，
  弹窗期应出现 4 条 popup 记录的搜索与其中一条命中）；③ 截图 + 日志归档到 `docs/verification/m2/t2-2/`。

   → 该阶段之外（含常驻守护待命期间）**不做弹窗检查**。`requirements.md` FR-01 触发行与 §2.1 活动弹窗行已同步
   （原「常驻守护下常驻每轮检查」已删除）。
   实现含义：守护待命期的预期集合为空 = 不搜；进入该阶段的判断由 T2-1 设计时给出方案（不得引入全扫兜底）。
2. **先演练、后实点**：真实点击**由用户执行**——用户操作设备并逐步告知当前界面状态，我负责核对识别结果、
   动作序列与判定证据；AI 不代用户点真实界面。
3. **复现账号已就绪**：**小号先完成一局对局即可消除新手引导 / 新手大厅**（2026-09-13 用户实测口径）；
   服务器列表显示账号等级，可据此确认所用小号是否为未过引导的新号。
4. **性能手段留 M5**：M2 不做窗口收紧 / 多尺度粗定位等优化；若某轮耗时影响动作节奏，如实记录并交由 M5。
5. **FR-02 移除**：新手引导 / 新手大厅的处理逻辑**不做**（`requirements.md` §1.1、§1.2、§1.3、§2.1、§3.1、§4 已同步，2026-09-13）；
   理由 = 账号打完一局后这两个界面不再出现，投入使用的账号可先手动过掉；恢复条件 = 后续出现无法先打完一局的账号时重新评估。
6. **弹窗阶段入口 = 命中「启动页」**（2026-09-13 用户拍板，落实第 1 条遗留的"进入该阶段怎么判断"）：
   守护待命的期望集合**不是空的**——只搜「启动页」（不搜它就没有任何办法知道游戏进入了「启动页 → 进入大厅」这一段；
   成本 = 一个小窗口信号，真机 7~22ms）；**命中启动页才注入弹窗期集合**
   {启动页 ∪ 选择服务器 ∪ 活动弹窗 ∪ 大厅}，命中大厅即收回待命。弹窗期带上「启动页」是因为它可能再次出现
   （返回启动页 / 换区），且滞回确认要走完 2 次命中。阶段推进用**本轮原始命中**，不等滞回结论
   （等 2 轮会让刚弹出的弹窗在本轮与下一轮都搜不到）。
   副作用（如实记录）：① 待命期停在农场等界面时状态显示为「未知」——不搜即不认识，这是"预期集合驱动、不兜底"的必然结果；
   ② 节流档位判据未改（仍为"命中当前状态才算稳定轮"），故待命期以 1s 档运行，性能优化留 M5（见第 4 条）。
