# 文档体系说明

> `docs/` 是本项目的文档根目录：其中 `requirements.md` 为需求层（唯一权威），其余为实现层文档。
> 需求层与实现层严格分离，规则见根目录 `AGENTS.md`。

## 目录索引

| 文件/目录 | 职责 | 更新时机 |
| --- | --- | --- |
| `requirements.md` | 需求与验收口径（唯一权威，需求层） | 只随需求变更修改，禁止回填实现手段 |
| `glossary.md` | 术语唯一定义处 | 出现新术语时先加这里 |
| `architecture.md` | 架构、模块边界、开放决策清单 | 结构变化时 |
| `progress.md` | 活文档：进度、下一步、证据链接 | 每个任务结束后追加 |
| `plans/` | 里程碑计划 + 任务卡 + 验收清单 | 计划变更或任务完成时 |
| `decisions/` | ADR：不可逆决策 | 做不可逆决策时 |
| `verification/` | FR/NFR ↔ 证据对照总表 | 里程碑收尾时 |
| `recognition/` | 识别样本与指标报告 | 每次回放 / 标定后 |

## 维护规则

1. **需求不回填**：`requirements.md` 禁止写入实现手段；实现细节只进本目录。
2. **一决策一 ADR**：影响面大或难以回退的决策必须留档。
3. **progress 只追加**：历史条目不删改；错误更正用新条目说明。
4. **证据可复现**：所有"已验证"结论必须附命令、报告或日志路径。
5. **术语统一**：写作先查 `glossary.md`，找不到先加词条再写文档。
