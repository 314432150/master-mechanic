# ADR-006：配置存储方式

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-09-13 |
| 状态 | 接受 |
| 关联需求 | FR-03（配置需持久化，重启后仍在）、FR-07（悬浮窗位置需持久化）、§1.3（失败必须明确提示，不得静默失败）、红线 4（零设备绑定常量）；M3-T3-1 |

## 背景

M3 有两类数据必须跨进程存活：

1. **巡查配置**（FR-03）：有序的「区服名称 + 目标好友名称」列表——丢了用户要重新录一遍，**丢失有后果**；
2. **悬浮窗位置**（FR-07）：拖动结束后吸附的边缘与纵向位置——丢了只是回到默认位置，**丢失无后果**，
   但**每次都回到默认位置**同样不可接受（FR-07 明确要求持久化）。

现状：代码库**没有任何键值存储**（全库无 `SharedPreferences` / `DataStore`）。唯一的持久化先例是标定产物：
应用私有目录文本文件 + 纯函数编解码（`CalibrationCodec`）+ 「临时文件写完后 rename」防半写（`CalibrationStore`）。
该模式已被 T1-5l / T2-3 反复真机核对（含"覆盖写入落后一次编辑"缺陷的排查），文本透明、可离线复核、可 JVM 单测。

## 决策

**统一沿用「应用私有目录文本文件 + 纯函数编解码 + 临时文件 rename」**，两类数据各自一个文件：

| 数据 | 位置 | 格式（首行恒为 `format=` / `version=`） |
| --- | --- | --- |
| 巡查配置 | `files/patrol/config.txt` | `format=mm-patrol` / `version=1` / 每项一行 `item=<区服名>|<好友名>` |
| 悬浮窗位置 | `files/floating/window.txt` | `format=mm-floating` / `version=1` / `side=<left\|right>` + `y=<像素>` + `screen=<宽>x<高>` |

约定：

1. **编解码是纯函数**（只依赖 `kotlin` / `java.io`，不依赖 `Context`）→ 全部语义（校验、往返、版本、
   损坏拒收）可在 JVM 单测覆盖；`Context` 只出现在"文件路径"这一层。
2. **写入恒为临时文件 + rename**（掉电 / 被杀不会留下半写文件被当作有效配置读入）。
3. **损坏 / 版本不受支持时按数据类型分流**（不搞"一律静默降级"）：
   - 巡查配置：**抛错并在界面明确提示 + 给出"清空重建"入口**——配置丢失有后果，静默变空等于骗用户（§1.3）；
   - 悬浮窗位置：**回落默认位置并重写文件**——位置丢失无后果，为此把界面卡住反而更糟；
     但**必须写日志**说明发生了什么（可审计）。
4. **坐标用像素 + 记录当时的屏幕尺寸**：恢复时按当前屏幕 clamp 回屏内（换分辨率 / 旋转后仍"始终可被找回"，
   FR-07）。
5. **零设备绑定常量**（红线 4）：文件里只出现**用户自己输入的名称**与**运行时读到的屏幕尺寸**，
   代码中不出现任何具体分辨率 / 密度 / 坐标（默认位置由屏幕尺寸运行时计算）。

## 备选方案

| 方案 | 放弃理由 |
| --- | --- |
| `SharedPreferences` | 键值少、Android 原生，但：① 语义（校验 / 顺序 / 版本）无处安放，只能写进调用方，**无法纯 JVM 单测**（要 Robolectric 或退化成 androidTest——本项目至今零 Robolectric 依赖）；② 落盘为 XML，排障与离线复核不如纯文本；③ 与既有标定产物两套模式并存，维护面变大。 |
| `DataStore`（Proto / Preferences） | 需**新增依赖**（`AGENTS.md`：新增依赖前先说明用途并征得确认），带来协程 / Flow 优势，但本项目只需"进页面读一次、改一次写一次"，收益不足以换一个新依赖与一套新 API。 |
| JSON（手写或引库） | 手写 JSON 要自己处理转义与非法输入（比行式文本更容易写出"半解析"的坑）；引库则同样是新增依赖。行式文本已被标定产物验证过：错误定位到行、格式漂移能被显式暴露。 |
| 与标定产物合并进同一个文件 | 两者的生命周期完全不同（产物随会话重建加载、配置与位置随时改），合并会让"改位置"触碰识别产物文件——**风险互换毫无收益**。 |

## 后果

- **引入的约束**：
  1. 名称类字段**不允许包含分隔符 `|` 或换行**（编码层显式拒收并提示，不静默替换）——
     真机上的区服名 / 好友名不会含这两个字符；
  2. 每次编辑都是"读盘 → 改 → 落盘"的一个小文件（KB 级），无需缓存与并发控制；写入仍在 IO 线程执行，
     不阻塞 UI；
  3. 配置与位置各有独立的 `format=` / `version=`，将来字段扩展走版本号，**不猜测旧格式**（同产物侧口径）。
- **收益**：零新增依赖；编解码与校验可 JVM 单测；文件透明，真机取证可直接 `run-as cat` 出来核对
  （`_tmp_check\adb-cat.ps1` 已有现成手段）。
- **边界（如实记录）**：文本文件不是事务型存储——同一进程外的并发写（例如两个进程同时写）没有防护。
  本项目只有单一应用进程写入，故不引入文件锁；若将来出现多进程（如独立配置进程），需重新评估。
