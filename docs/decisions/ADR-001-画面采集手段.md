# ADR-001：画面采集手段

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-09-11 |
| 状态 | 接受 |
| 关联需求 | §1.3、FR-09、§5-6、NFR-01、NFR-03 |

## 背景

识别层需要持续的屏幕画面数据。必须在非 root 前提下取得画面流，并满足：

- 采集授权由用户在系统层面授予、可撤销，缺失时必须可被检测并提示（§1.3）；
- 采集会话的终止语义要与 FR-09 的"会话区分"对齐：「用户切到别的应用」不等于会话终止；
- 采集不得改变识别结果（§5-6）；单帧处理耗时受 NFR-01 约束；包体受 NFR-03 约束。

## 决策

采用**系统屏幕采集（MediaProjection）+ 虚拟显示（VirtualDisplay）+ 帧缓冲（ImageReader）**，由前台服务承载采集会话：

1. **授权**：由前台 Activity 发起系统采集授权（`MediaProjectionManager.createScreenCaptureIntent()`），授权结果只用于**一次**采集会话——凭证不可缓存复用、同一实例不可多次创建虚拟显示（Android 14 起系统强制，违反即抛 SecurityException）。
2. **承载**：采集期间保持一个 `mediaProjection` 类型的前台服务；Android 14（目标 API 34+）要求**先启动该类型前台服务、再创建采集会话**，且会话期间服务类型保持不变，否则 SecurityException 或系统自动终止采集。
3. **会话终止**：注册 `MediaProjection.Callback.onStop`（必须注册，否则创建时抛 IllegalStateException），作为"采集会话终止"的唯一信号（用户主动停止 / 系统回收）→ 停止识别循环并引导重新授权；「用户切到别的应用」不触发该回调，不终止会话。
4. **画面参数**：分辨率、密度等全部在运行时从系统读取，不出现任何与开发设备绑定的常量。
5. **尺寸变化**：旋转等配置变化用 VirtualDisplay 的 resize + setSurface 更新，不重建会话。
6. **采集范围**：优先单应用——Android 14+ 引导用户在系统授权流程中选择"共享一个应用 → 目标游戏"（该路径不含本应用悬浮窗，且目标应用不可见时系统空白化捕获内容）；Android 9–13 无此系统能力时回退整屏采集。识别层不得依赖跨应用画面（与"非游戏前台零点击"语义一致）。

## 备选方案

| 方案 | 放弃理由 |
| --- | --- |
| 无障碍服务截图接口（AccessibilityService.takeScreenshot） | 仅支持 API 30+（Android 11 起），无法覆盖 Android 9/10；且与主路径并存会形成两条像素管线，违反"同数据同结果"的可复现要求（§5-4） |
| adb / 宿主侧截图 | 依赖与电脑连接，普通用户场景不可用 |
| root 采集类方案 | 违反 §1.3 非 root 前提 |

## 后果

- 每次采集会话都需用户授权（Android 14 起为强制），"会话终止 → 重新授权"是常态路径，必须在授权流中有明确状态展示与操作引导，禁止静默失败（FR-08）。
- 悬浮窗与采集的交互分两条路径：**单应用路径**（Android 14+，只采集目标游戏窗口）下本应用悬浮窗不进入画面；**整屏路径**（Android 9–13，或用户在弹窗中主动选择整屏）下**本应用悬浮窗会进入采集画面**，识别层必须对悬浮窗的开关、位置、展开态不敏感（§5-6），由 M1 标定的对照样本覆盖。
- 单应用路径下目标应用不可见（后台 / 锁屏）时系统会空白化捕获内容——与「非前台零点击」互为印证；但捕获空白**不可**用作前台判定的替代实现，ADR-005 仍是前台判定的唯一口径。
- 熄屏 / 锁屏时画面可能停止更新：识别循环按"无新帧"处理；结合 ADR-005，锁屏时前台判定为"非前台"，不点击、不消耗滞回计数（FR-09）。
- Manifest 需声明 FOREGROUND_SERVICE 与 FOREGROUND_SERVICE_MEDIA_PROJECTION（Android 14+），并伴随常驻通知（FR-08）。
