# ADR-010：无障碍自愈（应用自持一条特权权限）

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-10-25 |
| 状态 | 接受（真机验证通过；用户 2026-10-25 拍板"开干"） |
| 关联 | FR-08（授权必须由用户在前台确认）、`requirements.md` §NFR（安装后可用性）；实现 `auth/AccessibilitySelfHeal.kt` |

## 背景

无障碍服务是全流程**唯一每次覆盖安装都可能掉、且只能钻进系统设置手点**的授权（真机反复踩：装完显示"去开启"、点了没反应）。
用户发现同类工具 GKD 能自行开关无障碍，我读了它的 `start.sh` 后在本机做了探针，得到两条实测结论：

1. **`adb shell settings put secure enabled_accessibility_services` 会被拦**（vivo / Android 16，写入不生效）；
   但**应用在自己的进程里**写同一个键**会被接受** —— 只要它持有 `WRITE_SECURE_SETTINGS`；
2. 该权限是 `development` 级，只能 `adb shell pm grant` 授予；**普通 / release 包同样有效**（GKD 即如此），
   且**覆盖安装会保留**，只有卸载重装才需重授。

探针日志（`docs/progress.md` 2026-10-25 20:24）：写入前列表 1 项 → 写入后 2 项 → 同一进程内 `无障碍查询 → 已开启（命中本应用组件）`，
`dumpsys accessibility` 里 `Bound services` 出现 `Service[label=MasterMechanic …]`。

## 决策

**加一条可选特权**：清单声明 `WRITE_SECURE_SETTINGS`，由 `AccessibilitySelfHeal` 在**冷启动时**
"发现被关就自己开"。四条边界写死在代码注释与本文件里：

1. **只动自己**：加/删都只针对本包那一项 —— 绝不移除别人的无障碍服务，也绝不改别的设置键。
   （2026-10-25 修正：原先写的是"只开不关"，但用户要求授权页那颗开关**双向**可用 ⇒
   "关"由**用户亲手拨**才发生，且只摘自己；冷启动自愈仍然只开不关。）
2. **用户亲手关掉就不再抢**：开关拨关时写一份"用户主动关闭"标记，冷启动自愈见到它就跳过；
   拨开时清掉该标记。→ 否则关掉后下次启动又被打开，等于跟用户对着干；
3. **冷启动自愈只跑一次**（每进程一次），不是轮询；
4. **没有权限就完全静默**：只打一行日志，行为与加这个能力之前**一字不差**（那颗开关点击只把你送到系统设置页）；
5. **写失败如实记**：不重试、不刷屏；日志能区分"没权限"与"系统未采纳"。

## 备选方案

| 方案 | 放弃理由 |
| --- | --- |
| 集成 **Shizuku**（用户最初提议） | 本机实测：Shizuku 与 adb 同为 uid 2000，**同样写不动**那个设置；它换来的只是"少点两下"，代价是架构级第三方依赖 + 每次重启手启 + 双模式回落 ⇒ 不值。GKD 真实用的也是 `WRITE_SECURE_SETTINGS`，不是 Shizuku |
| 要求用户每次装完手动 `adb` 一条命令 | 也是"adb 一次性授权"，但把体验压给用户；本方案让**App 自己**用这条权限，命令只需跑一次 |
| 让无障碍服务自己 `disableSelf()` / 轮询重开 | 服务被系统停掉后根本不会再执行代码，自愈无从谈起 |
| 直接把无障碍换成 Shizuku 注入点击 | 红线 3 / ADR-002 全都得重审，且 shell 注入的"合成事件"痕迹与无障碍一样在；收益不成立 |

## 后果

- **代价 1（安全模型）**：App 持有一条 `WRITE_SECURE_SETTINGS`，理论上能改任意 secure 设置。缓解：
  代码里只有 `AccessibilitySelfHeal` 一处使用，且只写那一个键、只追加自己（有单测钉住"不删除别人"）。
- **代价 2（行为边界）**：用户"主动关掉无障碍"会在**下次冷启动**被覆盖。已接受 —— 若将来用户抱怨，
  再加一个"自愈开关"（默认开）。
- **代价 3（分发）**：`WRITE_SECURE_SETTINGS` 不通过 Play 分发时无需申报；若上架需单独评估（本项不通过 Play 分发）。
- **约束**：`adb shell pm grant <pkg> android.permission.WRITE_SECURE_SETTINGS` 必须在**首次安装后**跑一次；
  之后覆盖安装自动保留。装机流程里由我代跑。
- **不影响既有红线**：点击注入仍走无障碍 `dispatchGesture`（ADR-002 不变），本决策只解决"授权怎么自动就位"。
