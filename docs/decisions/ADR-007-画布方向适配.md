# ADR-007：画布方向适配

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-09-12 |
| 状态 | 接受 |
| 关联需求 | §5-1、§5-5、§1.2、NFR-01、红线 4、红线 7；M1-T1-11 |

## 背景

识别产物的模板与搜索窗口都以**标定画布**为坐标系；而采集画布尺寸由**建会话那一刻的系统显示方向**决定、
会话内冻结（`CaptureService.startSession` 读一次 `resources.displayMetrics`；全库无旋转 / 重设处理）。
真实用户环境下建会话时机不可控：系统授权弹窗默认「共享一个应用」，选中目标应用后系统把游戏带回前台
→ 画布为横画布 3168×1440，与竖画布标定产物 1440×3168 不一致。

此时旧实现按「**整幅画布比例**」换算窗口，位置直接错位（实测纵向偏约 247px，而窗口本身高 111px）
→ 识别全失效（真机实录 4 次：T1-5 / T1-7 / T1-9 / T1-10d）。

T1-11a 测量给出精确映射（`../recognition/research/research-canvas-orientation.md`）：
**不存在旋转；画面等比缩放 + 居中**（横画布帧 → 竖画布坐标 = ×2.2 + 平移 1256，内容带高 655 实测）。

## 决策

**在识别层做「按画面区的运行时归一」**——不改采集画布，把运行帧摆回标定几何后再判定：

1. **几何模型** `CanvasGeometry`（纯逻辑，T1-11c）：画面长宽比 = 标定画布长边 / 短边；任一张画布内
   画面区 = 该比例的矩形**等比缩放并居中**（contain + center，起点 floor、长度四舍五入，确定性）。
   标定画布内的画面区是居中窄带，转置尺寸画布内是整幅。
2. **帧归一** `FrameNormalizer`（纯逻辑）：运行帧灰度按几何映射重采样到**标定画布几何**，只填各信号
   窗口覆盖的像素（判定只读窗口内像素，T1-10b 同口径）；画面区与标定一致时**直接返回原帧**
   （零拷贝零开销——常见竖画布会话的开销与改动前完全相同）。
3. **接入**：`CalibrationData.toLoop()` 以产物 `frame` 尺寸建立几何 → `RecognitionLoop` 在检测前归一；
   采集层的窗口化灰度区域改为「标定窗口映射到运行帧」的区域（含采样外扩），保证归一化有足够源像素。
4. **判定语义不变**：模板 / 窗口 / 参数 / 阈值一律沿用产物，归一只是把输入摆回标定几何。
   转屏过渡帧（内容被 90° 旋转满幅，研究文档 §9）不做特殊处理——旋转内容与模板 NCC 低（实测 ≤0.28）
   → 自然落为未命中；滞回「进入需连续 2 次命中」再过滤单帧。

## 备选方案

| 方案 | 放弃理由 |
| --- | --- |
| 产物多方向变体（按方向生成模板 / 窗口变体） | 需运行期缩放模板（该方向的有效性本次未验证），产物多一份派生状态、标定与运行的一致性更难保证，收益与所选方案相同 |
| 只换算窗口（不换帧、不换模板） | 仍需模板随尺度缩放、分数可比性未验证；窗口换算绕不开「画面区」中介，等于所选方案的子集且风险更高 |
| 采集层把画布固定为横屏尺寸 | ① 写死分辨率违**红线 4**；合法变体（按显示实时尺寸导出长边 / 短边）仍依赖「游戏恒横屏」这一未全场景验证的假设，把「两向都可能失效」换成「只服务横屏」，与 T1-11 目标相反；② 成本反向：内容满幅后模板 / 窗口像素面积 ×4.84、匹配量约 ×23（NFR-01 已 16 倍超标）；③ 需重标定（产物 frame 维度变化，固定批次与指标报告回归重建）。反之，竖画布「缩小嵌入」把识别成本压到 1/23 |
| 会话内监听旋转并重建 VirtualDisplay | 重建会中断帧流、反复重置识别循环（含滞回状态），且不解决「内容已被缩小」的尺度问题，成本同上一行 |

## 后果

- 同一标定产物在竖 / 横画布会话下均可用：**不需要重新标定**，也不依赖用户姿势与旋转锁定。
  会话建立后画布方向仍不可控，但不再影响识别（只是画面区不同）。
- 方向不同的会话多一次 ROI 重采样（当前场景源区约 865×244 → 目标 393×111）与更大的灰度转换区域；
  同方向会话零开销。归一化耗时计入「识别段」口径（T1-9 分段统计）。
- 判定位置仍以**标定画布坐标**输出（与判定记录口径一致），M2 点击按同一坐标系使用。
- 边界（如实记录）：画面区模型基于「目标画面铺满显示长边」（本设备实测成立）；若目标应用自带黑边
  （画面比例 ≠ 设备比例）需另测后扩展模型；转屏过渡帧不识别但不误报（浪费 1~2 轮，无额外检测开销）。
