# ADR-003：识别技术路线

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-09-11 |
| 状态 | 接受 |
| 关联需求 | §2.1、§5（1–6）、NFR-01、NFR-02、红线 3、红线 7 |

## 背景

识别是全部动作的前提：识别不可信时，后续所有点击都建立在错误判断上。需在非 root、端侧运行（NFR-01：单帧 < 20ms）且包体受限（NFR-03）的前提下选择技术路线，使 §5 六条要求全部可成立：判定记录可审计（分数 / 位置 / 竞争位置）、不可信可判定、三类抗干扰、结果可复现（同数据同参数同结果）、能力在目标设备上自标定（零设备绑定常量）、不受悬浮窗影响。

识别对象分两类：**标志类**（界面标志、弹窗关闭控件、新手标志等，闭集）与**名称类**（区服名 / 好友名，由用户配置的开放集）。

## 决策

**两条腿：标志类走确定性模板匹配，名称类走文字识别方向。**

1. **标志检测：归一化模板匹配（局部搜索窗口 + 多模板）。**
   - 一个标志可有多个模板（如活动弹窗「需覆盖多种样式」），模板随设备在标定阶段采集（T1-5），代码零设备绑定参数；
   - 匹配只在标志的搜索窗口内进行：窗口按相对比例定义（随帧尺寸换算），如 FR-01 仅右上角局部范围；
   - 输出**相似度分数 + 位置**，同画面保留多个峰值候选——最高分与次高分天然构成 §5-1 的「竞争位置」与 §5-2 的「不可信」判据；
   - 相似度对亮度 / 对比度做归一化（§5-3 ② 背景动态下仍可稳定），对局部半透明遮罩有一定容忍（§5-3 ①，标定时以「悬浮窗 开 / 关 / 位置 / 展开态」对照样本核对 §5-6 一致性）；
   - 算法为确定性数值计算、不依赖安卓框架：输入帧数据 → 输出判定，可在 JVM 离线回放（§5-4）；同一目标设备内游戏渲染尺寸稳定，匹配尺度由标定确定，不做运行期多尺度猜测。
2. **名称定位：文字识别方向（列表区域局部执行 + 精确匹配）。**
   - 名称是开放集，无法预采模板；对应 FR-04 第 5 / 9 步「在一堆外形高度一致的目标里挑一个」，是 §5-3 ③ 的核心场景；
   - 本 ADR 锁定方向与能力边界：识别 + 精确字符串匹配；匹配不唯一 / 不一致一律视为未找到（红线 3），多候选按不可信处理（§5-2）；
   - 具体实现选型与精度验证在首次实现名称定位的任务中进行（M4 前置）；在验证通过前，相关步骤保持「停下并提示」行为。
3. **分层约束（沿用）：**识别层保持纯逻辑（输入帧数据、输出判定），不依赖安卓框架；模板、搜索窗口、阈值全部来自标定产物（T1-5）；识别循环的检测间隔按 NFR-02 自适应。

## 备选方案

| 方案 | 放弃理由 |
| --- | --- |
| 特征点匹配（ORB 类） | 小图标与文字区域可提取特征少、不稳定；含随机采样过程，与 §5-4「同数据同结果」冲突风险高；匹配置信度语义弱于归一化分数，不满足 §5-1 的可审计口径 |
| 端侧深度学习检测 | 与 NFR-01（单帧 <20ms）、NFR-03（≤25MB）空间紧张；训练数据采集与标注成本与项目规模不匹配；置信度语义无法直接给出 §5-1 的竞争位置 |
| 纯文字识别（覆盖标志类） | 农场入口、返回按钮等图标类标志无文字，覆盖不全，只能作补充 |
| 直接像素比对 | 对 §5-3 ① 遮罩、② 背景动态无鲁棒性：无归一化的差值无统计意义，无法支撑 §5-2 的不可信判据 |

## 后果

- 标定流程成为能力基石：每台目标设备生成「模板 + 搜索窗口 + 阈值」全套产物（T1-5），全链路零硬编码（§5-5）；
- 判定记录（分数 + 位置 + 竞争位置）在识别层数据结构上天然可审计，点击审计链（NFR-05）由此接上；
- 模板匹配对显著透视 / 缩放变化敏感——同设备内游戏 UI 渲染稳定（标定兜底）；若后续发现特殊界面渲染规格不一致，在多模板机制内增补，不引入运行期多尺度猜测；
- 名称定位的文字识别精度是最大技术风险，集中在 M4 前置任务消解；验证前保持「停下并提示」的安全行为；
- 悬浮窗对照样本（开关 / 位置 / 展开态 × 标志）并入回放样本集，§5-6 的验收证据直接由此产出。
