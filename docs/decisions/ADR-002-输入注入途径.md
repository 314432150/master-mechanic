# ADR-002：输入注入途径

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-09-11 |
| 状态 | 接受 |
| 关联需求 | §3.2、§4、NFR-05、NFR-06、红线 2、红线 6 |

## 背景

一切点击必须由程序下发，且只发生在四种合法来源下（红线 2）；相邻点击间隔 ≥300ms 必须由统一实现点保障，不依赖调用方自觉（红线 6）；每次点击必须可审计（NFR-05）。需要在非 root 前提下选择输入注入途径，并同时确定"间隔 ≥300ms 的唯一实现点"。

## 决策

采用**无障碍手势注入（AccessibilityService.dispatchGesture，API 24+）**作为唯一注入通道。

**唯一实现点：执行层的"点击转发器"（单一组件）。** 所有调用方（FR-01、巡查主流程、悬浮窗菜单；FR-02 已于 2026-09-13 移除）只能经它下发点击，全部约束由它承担：

1. **门禁**：非前台（ADR-005 信号）或状态未知 → 拒绝下发并记录，绝不试探（红线 1、§4-2）；等待期间门禁在真正下发前复核一次；
2. **间隔**：以单调时钟计量，前一次手势**完成**到下一次手势**开始**不低于 300ms，不足则等待——该口径比"开始到开始"更保守，兼容 NFR-06 的任何解释；
3. **串行**：同一时刻只允许一个手势在途；派发失败或被打断（onCancelled）一律按"点击未完成"处理，交由步骤验证失败路径，不盲重试（红线 5）；
4. **审计与来源**：每次下发必须携带判定记录 ID 与来源枚举（四类合法来源之一），构成 NFR-05 的点击审计链。

其余实现约束：点击以短行程 stroke 实现；坐标一律来自识别判定结果；服务配置声明手势能力（canPerformGestures）。

## 备选方案

| 方案 | 放弃理由 |
| --- | --- |
| 无障碍节点 performAction（按节点点击） | 游戏画面为自绘引擎渲染，节点树中不存在游戏内的按钮控件，无法给出可靠坐标；且 §4-4 要求按识别结果定位 |
| adb shell input 类方案 | 依赖与电脑连接，普通用户场景不可用 |
| root 注入（injectInputEvent 等） | 违反 §1.3 非 root 前提 |
| 插桩测试类注入 | 需要调试签名与测试环境，非交付形态 |

## 后果

- 注入能力完全依赖无障碍服务：服务不可用 = 不能点击；与 ADR-004、ADR-005 共用同一服务，整体按"不可用即停"处理（宁可停住，不可乱点）。
- 手势可能被系统打断（取消回调），流程必须把"点击未生效"当作正常失败来处理——与 FR-04"动作后必须验证"机制天然一致。
- 未来的长按/滑动（如 FR-04 第 4 步的滚动查找）同样经该转发器下发，自动继承串行与间隔约束。
- 本方案不设计任何"隐蔽注入"；与游戏交互的手段限定在无障碍与屏幕采集的公开能力内（§1.3）。
