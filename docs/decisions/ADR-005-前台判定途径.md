# ADR-005：前台判定途径

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-09-11 |
| 状态 | 接受 |
| 关联需求 | FR-09、FR-05、红线 1 |

## 背景

FR-09 要求前台判定必须是**独立信号**——不得以"没有识别到任何标志"代替；判定失败一律按非前台处理；状态变化后 2 秒内生效。该信号同时是"是否允许点击"（红线 1）、悬浮窗可见性（ADR-004）与巡查暂停（FR-05）的输入。

## 决策

以**无障碍服务的窗口信息**为信号源，输出布尔量"目标应用是否在前台"：

1. **数据来源**（双来源互为兜底）：
   - 订阅窗口变化事件（TYPE_WINDOW_STATE_CHANGED、TYPE_WINDOWS_CHANGED；后者与 getWindows() 均需开启 FLAG_RETRIEVE_INTERACTIVE_WINDOWS）；
   - 并按需主动查询"当前活动窗口"（getWindows() 中 isActive 的窗口）。
2. **判定规则**：活动窗口所属应用包名 == 目标应用包名 → 前台；否则 → 非前台（包括锁屏、系统界面、其他应用、本应用自身界面与悬浮窗）。
3. **生效延迟**：事件链路通常在一秒内生效；另有不超过 2 秒的主动复核兜底，防止丢事件。
4. **判定失败即非前台**：服务未连接、查询为空、读取异常 → 一律输出"非前台"（FR-09），不点击、不推进、不消耗滞回计数。
5. **独立性**：不使用任何画面内容参与判定，与识别层严格分离。

## 备选方案

| 方案 | 放弃理由 |
| --- | --- |
| 使用情况统计接口（UsageStatsManager）轮询 | 需额外"使用情况访问"特殊授权；轮询时效与可靠性均劣于窗口事件 |
| 任务/进程查询接口（ActivityManager 等） | API 21+ 起对第三方仅返回自身应用信息，不可用 |
| 用识别结果代替（"未命中任何标志"≈非前台） | FR-09 明确禁止：加载页、黑屏同样识别不到标志，二者是两件事 |
| 扫描 /proc 进程状态 | 受系统限制且行为不稳定，不可靠 |

## 后果

- 前台判定、注入（ADR-002）、悬浮窗（ADR-004）共用同一个无障碍服务：服务不可用 → 三者同时停机，整体按"非前台"处理（宁可停住，不可乱点）。
- 自身窗口不会造成误判：判定只看"活动（焦点）窗口"，本应用悬浮窗不可聚焦、永不成为活动窗口；本应用前台配置界面则会正确得到"非前台"。
- 该信号是红线 1 的运行时闸门：执行层每次下发点击前必须读取本信号（见 ADR-002 门禁）。
