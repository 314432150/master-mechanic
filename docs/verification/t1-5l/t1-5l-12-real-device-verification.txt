二、核对发现的缺陷与修复（如实记录）
----------------------------------------------------------------

缺陷：**参数编辑写入落后一次编辑**（界面 0.86 / 产物 0.800000）。

- 现象：清空「命中线」后输入 `0.86`，界面文本为 `0.86`，产物文件 `params=0.800000`（上一次编辑的值）。
- 根因：`CalibrationRoute` 里的 `applyParams()` 使用了**组合期计算出的快照值**——
  `val editedParams = CalibrationSignals.parseParams(thresholdText, …)` 与 `val artifact = remember(…) { … }`；
  文本变化回调触发的写入读到的仍是上一帧组合的解析结果，因此稳定落后一次编辑。
- 修复（`ui/CalibrationScreen.kt`）：
  1) 参数解析改为在 `applyParams()` 内**实时读取**编辑框（局部委托属性读取即时），不再用 `editedParams` 快照；
  2) 写入基线改为在 IO 线程**现读盘上产物**（`CalibrationStore.load`），不再用 `artifact` 快照；无产物时不写
     （参数随首个信号写入）；
  3) 同类隐患一并消除：删除单条信号改为「读盘 → 删 → 写回」，工作台写入改为实时解析参数
     （`writeSignalFromSelection(params = parseParams(thresholdText, …))`）。
- 复测：同一输入序列（0.85 → 清空 → 0.86）产物即 `0.860000`；改回 0.85 → `0.850000`；见 [t1-5l-10]。
- 回归：修复后 `:app:testDebugUnitTest` + `:app:assembleDebug` 通过（27 套件 198 例零失败）。

中间态记录（如实）：输入 `0.86` 过程中会依次出现 `0` / `0.`（非法，不写）与 `0.8`（合法，落盘）→ 最终 `0.86`。
这是「编辑合法即写入」的固有行为（每次合法变化都落盘），属预期。

四、环境事实（记录备查）
----------------------------------------------------------------

- 无线调试同一设备会同时登记多个 transport（`192.168.1.225:3035` 与 4 个 mDNS tls-connect 条目），
  多设备冲突时报 `more than one device/emulator`，需以 `-s` 指定。
- 重装 APK 后 vivo 会撤销无障碍授权，应用启动时自动跳系统无障碍设置页（同 T0-2）；本核对只需进标定页，
  不受影响。
- tapping 参数输入框后系统弹出**数字键盘**并改变布局坐标；收键盘用 `input keyevent 4`（键盘显示时 BACK
  只收键盘；键盘未显示时 BACK 会返回上一页——本次曾因此误退出到桌面，随后按新坐标重做）。
- PowerShell 下截图/取产物文件必须用字节级通道：`adb shell screencap -p /sdcard/x.png` + `adb pull`，
  以及 `Start-Process … -RedirectStandardOutput`（PowerShell 的 `>` 重定向会破坏二进制/编码）。
- 全程为测试侧 adb 注入（点击 / 拖动 / 文本），应用侧零点击口径不受影响（红线 1 / 2 延续）。
