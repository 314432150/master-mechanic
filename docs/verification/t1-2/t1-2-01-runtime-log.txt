===== 时间线解读 =====
1. 建立（21:19:22.192）：系统授权通过后服务启动，INACTIVE -> ACTIVE（来源: 用户授权会话建立）。
2. 维持（21:19:32–21:20:12）：帧管线以 ~60fps 接收（600+ 帧/10s 窗口），节流后每窗口处理 10 帧（T1-2 固定 1s 间隔）；
   帧尺寸 1440×3168 为运行时从系统读取，非代码常量。
3. 切走不终止（21:20:12–21:22:51，约 2.5 分钟）：HOME 切走后无任何终止日志；期间无帧到达 →
   无统计输出（单应用模式目标不可见时系统空白化捕获，与 ADR-001 预期一致）；
   dumpsys media_projection 确认会话保持活跃（见 t1-2-06-dumpsys.txt）。
4. 帧管线恢复（21:22:51.875）：游戏回前台后帧恢复，159665ms 合并窗口仅 569 帧（切走期无帧 + 恢复期帧），
   随后恢复 60fps 正常节奏——证明会话全程存活（「会话本身终止才停止循环」）。
5. 应用主动停止（21:23:35.358）：界面「停止采集」→ ACTIVE -> INACTIVE（来源: 应用主动停止）；界面回到「未授权」。
6. 重新授权（21:23:50.496）：INACTIVE -> ACTIVE（来源: 用户授权会话建立），进入第二会话。
7. 系统侧回收（21:26:45.885）：从系统控制中心停止屏幕共享 → MediaProjection.Callback.onStop 触发 →
   ACTIVE -> INACTIVE（来源: 系统侧回收）；服务停止、常驻通知消失、界面回到「未授权」（需重新授权，符合 ADR-001 会话制）。
   注：该操作同时启动了系统自带录屏（测试侧副作用，已通过计时条停止并确认 dumpsys 无残留会话）。
