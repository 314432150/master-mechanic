# UX 评审：标定页排版（2026-10-02）

> 评审人：`android-ux-designer` 子代理（资深 Android 交互 / 界面设计顾问）
> 触发：用户 2026-10-02 —— "目前标定页的排版感觉还是有点乱，操作步骤是采集画面、打开标定工作台进行标定、
> 查看编辑删除标定结果，有什么更高的排版布局方案吗？问问 UX 设计师。"
> 关联：`progress.md` 418；落地记录见 `README.md` 的 U5 节 5f / 5g。

## 结论先行

**推荐「分区 + 单一 `LazyColumn` + 状态驱动的单主 CTA」**：把两张卡片拆成"采样分区 / 结果分区"，
整页只留**一个主按钮**（随状态变：去授权 → 开始录制 → 停止录制 → 打开工作台），清单行进 `LazyColumn` 回收。

最大取舍：卡片外壳去掉后视觉分节变弱（与其它一级页的"卡片感"不一致）；换骨架要重测左滑与滚动。
**折中**：保留 Card、只减内薄（内边距 16→12、卡间距 12→8），也照样能把清单换成 `LazyColumn` 拿到大部分收益。

## 三个方案

| # | 方案 | 首屏第一眼 | 三步流程怎么表达 | 长清单 | 危险动作 | 代价 |
| --- | --- | --- | --- | --- | --- | --- |
| 一 | **原地重排**（不换骨架） | 要点行 → 采样卡标题 → 唯一主 CTA → 结果卡标题 + 摘要 | 靠卡片先后 + 每卡主 CTA 文案隐式表达 | 页内就地滚动，**不回收** | 「清空帧池」进卡头溢出菜单；「删除整个标定结果」留底部 + 16dp 隔离 + error 描边 | 成本最小；但"下一步做什么"仍要用户自己把两张卡连起来；清单性能与横屏首屏高度问题**没解决** |
| 二 ⭐ | **分区 + 单一 LazyColumn + 单主 CTA** | **状态指令句**（"下一步该干什么"）→ 帧数 + 主 CTA → 结果条数摘要 | 分区标题 **①/②** + 一句状态指令；**不引入 stepper** | 清单进 `LazyColumn`（回收，20+ 行只组合可视部分），筛选 chips 作 header item | 采样侧走溢出菜单；结果侧走页面**最底部的孤立危险区**（不与清单行相邻） | 中等；是本轮最值得花的一次改动 |
| 三 | 显式三步 stepper（顶部进度 + 单步聚焦） | 三段进度条 → 当前步展开区（只 1 个 CTA） | 最强，一眼看清全流程与进度 | 第 3 步展开时才组合 | 第 3 步展开区底部 | **不推荐**：① 回访查看是高频场景却要多点一次展开；② "当前步"要靠推断，推断错就把用户要的东西藏起来；③ 折叠让帧数/条数默认不可见 |

### 为什么推荐方案二

- **三步线性**：顺序感用"分区编号 + 状态指令句"就够了，不需要 stepper 组件，也就没有那套容易错的步态推断；
- **长清单**：`LazyColumn` 是唯一同时解决"20+ 行性能"与"首屏高度预算"的做法；
- **频繁回访**：回访时要的是"一眼看到帧数 / 条数 + 直接滚到某一行" ⇒ 状态必须**常驻不折叠**（否掉方案三）、
  清单必须**能长滚且回收**（否掉方案一）。方案二正好是这两条的交集。

## 当前实现最该修的三个问题（按严重度）

**P1（阻塞）整页 `Column.verticalScroll` 里用 `forEach` 铺 20+ 行清单**
进页面一次性组合全部行，每行还解一次位图；切换筛选后整页重排、滚动位置跳动；横屏（可视高 ≈216dp）
与分屏下主 CTA 必然在屏外。
改法：外层换 `LazyColumn`；卡 1 / 结果分区标题作 `item {}`，清单行作 `items(key = 行键)`；
页内 `.padding(16.dp)` → `contentPadding`；分组标题用**普通 item**（不用 `stickyHeader`，见无障碍）。

**P2（阻塞）两个危险动作长得像普通次要按钮，还紧贴高频操作**
「清空帧池」是默认色 `OutlinedButton`，与「开始录制」同排只隔 8dp；「删除整个标定结果」也是默认色，
**直接跟在清单最后一行下面、零间隔** —— 用户单手滚到底想点最后一行时，落点正好在删除上。
改法：两者统一 **error 前景 + 1dp error 描边**；「清空帧池」移入卡头溢出菜单；删除结果加 **≥16dp 隔离** +
"此操作不可撤销"，与"生效说明"合成独立危险区；确认弹窗按钮写结果名（"清空 42 帧"）而不是"确定"。

**P3（影响体验）首屏那行要点信息量为零，真正的"下一步"被藏在弹层里**
`本页录样本帧、管理标定结果与匹配参数。` 说的是"本页做本页的事"；而弹层里那句
"流程：先录样本帧，再进全屏工作台框选，点「写入」即落盘。"才是用户真正需要的。
改法：首屏换成**状态驱动的指令句**（4 条，各 ≤24 字，`maxLines = 2` 兜底、**不要设 1**）：
无会话 → "需要先授予屏幕采集权限才能录样本。"；有会话 0 帧 → "开启录制后切到游戏，各界面停留 2~3 秒。"；
有帧无结果 → "已有 N 帧，去工作台框选标志与锚点。"；有结果 → "标定 N 条已生效，可在下方查看或删除。"
同时把 `frames_hint` 改成**只在"有会话且 0 帧"时显示**，卡内常驻文字从 4 段降到 1 段。

## 唯一主 CTA 的状态机（一次点击只做一件事）

无会话 → `[去授予屏幕采集权限]`（filled）｜未录制 + 0 帧 → `[开始录制]`（filled）｜
录制中 → `[停止录制]`（filled / error 容器色）｜有帧无结果 → `[打开全屏工作台]`（filled）｜
有结果 → `[打开全屏工作台]`（filledTonal，视觉重心让回清单）。

## 关键规格

| 项 | 值 |
| --- | --- |
| 页面左右边距 / 分区间距 | 16dp / 12dp（保留卡片则卡内 16→12、卡间距 12→8） |
| 首屏高度预算 | 指令行 ≤48 + 采样分区 ≤96 + 结果摘要 ≤72 ≈ **≤216dp** |
| 按钮 | 视觉 40dp（M3 默认）/ 命中 ≥48dp；大字号允许增高、不许被裁 |
| 清单行高 | 56dp（已满足） |
| 间距 | 相邻可点目标 ≥8dp；**危险按钮与最近可点元素 ≥16dp** |
| 危险按钮 | error 前景 + 1dp error 描边 + 文字写明后果 |
| 分区标题 | 大分区 `titleMedium`、清单组 `titleSmall`；计数 `labelLarge` + `onSurfaceVariant` |
| 文案 | 指令句 ≤24 字；卡内常驻说明 ≤1 段；超 60 字进「说明」弹层且默认收起 |

## 无障碍（新骨架要守住的）

- **不要用 `stickyHeader`**：TalkBack 会把粘性标题归到列表头部语义位置 ⇒ "先念一遍组标题、滚到组里又念一遍"。
- 溢出菜单：`IconButton` 的 `contentDescription` = "更多操作（采集）"；菜单项要有可读文字；
  它是「清空帧池」的**可点路径**（不能只靠长按）。
- "录制中"的红点必须**同时有文字**，不能只靠颜色；筛选 chips 的选中态由 `FilterChip.selected` 自带语义承载。
- 已经做对、不要改回去的：清单行 `mergeDescendants` + `contentDescription` + `customActions` 删除；
  `SwipeActionRow` 只在 `revealFraction > 0` 时才组合删除按钮（常驻隐藏按钮会被读屏念出来）。

## 横竖屏与极端情况

- **横屏 / 分屏**（可视高 ≈216~400dp）：方案二下"指令句 + 采样分区 + 主 CTA"≈130dp 能落在首屏；
  建议 `maxWidth ≥ 600dp`（横屏 / 折叠屏展开 / 平板）改**左右两栏**：左栏状态 + 采样，右栏结果 + 清单。
- **大字号（1.3~2.0x）**：CTA 那块按 56~64dp 预留；清单行 56dp **固定高**在 2.0x 下会文字截断
  ⇒ 需复查 `SwipeActionRow` 的固定 `rowHeight`（左滑组件依赖固定高，要一并回归）。
- 软键盘：本页主体无输入框（备注编辑在弹层）⇒ 保证 `imePadding`。

## 落地顺序（每步可独立验收，本仓库已做第 1 步）

1. **文案与危险动作归位（不换骨架）** —— ✅ **2026-10-02 已做**（见 `README.md` 5f / 5g）。
   *做对了*：首屏卡内常驻文字 ≤1 段；深浅色 / 大字号下两个危险按钮一眼可辨；TalkBack 能从卡头菜单到达「清空帧池」。
2. **清单换 `LazyColumn`（骨架最小改动）** —— ⏳ 待做。
   ⚠ 设计师标记为**阻塞级风险**：左滑露删除与列表纵向滚动会抢手势
   ⇒ **先只搬一行做真机验证再铺开**（沿用 `ServerListGestures` 的横纵互斥判据与 `PointerEventPass`）。
   *做对了*：20+ 行滚动无掉帧；筛选切换后列表回顶；左滑仍能划出删除。
3. **分区化 + 横屏两栏** —— ⏳ 待做。减薄卡片壳、加分区编号与状态摘要、`maxWidth ≥ 600dp` 左右两栏。
   *做对了*：手机横过来，帧数、条数与最该点的那个按钮仍在首屏；2.0x 大字号下无截断。
