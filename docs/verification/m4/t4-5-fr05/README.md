## 2. 判定要点（为什么要这么看）

- **"不静默"是 FR-05 的核心**：每个结局（暂停 / 中止 / 完成）都必须**用户可见**——现在由**顶部标签常驻**
  承接（底部浮窗提示 2026-09-29 已按用户口径移除），读屏播报也归标签；⇒ 核对时**特别确认标签真的常驻**
  （历史坑：跑完那一枪之后 6ms 标签就被摘掉 ⇒ 用户看不到「已完成」，见 `progress.md` 第 3383 行附近的说明）。
- **"继续"必须是"从失败那步重试"**，不是重跑整条：看日志里**第一步是不是又要重来**。
- **暂停期间零动作**：`paused` 状态下 `PatrolRunner` 直接返回、不下发任何点击（红线 1/2 的延伸）。
- **中止后不自动重试**：这是硬性要求 6；确认没有"自动再来一遍"。

## 3. 四态流转关系（2026-10-01 从代码读出，核对时对照）

模型：`PatrolFlow.Outcome { RUNNING, FINISHED, FAILED }` + `State.paused`（**暂停不是第三种结局**，是
`RUNNING` 上的一个开关），外加"**停止**"（`PatrolSession.stop()` 把流程整个清空 ⇒ 标签回「待命」，
**不是** Outcome 的一种）。

| 当前 | 事件 / 触发者 | 变成 | 关键副作用 |
| --- | --- | --- | --- |
| （没有在跑） | 用户点菜单（换号 / 拜访 / 换号+拜访 / 只拜访） | **运行中** | 先过**起点判定**（起点不成立 ⇒ **不启动**并说明，不是"启动后立刻中止"）；`PatrolFlow.start` |
| 运行中 | **当前步验证通过**（`advance`） | 运行中（下一步） | `step +1`、`retries = 0`、**预算重新起算**、清"本步已下过击" |
| 运行中 | **验证不通过**（`fail`）且未到上限 | 运行中（**原地重试同一步**） | `retries +1`；不前进、也不回头重跑前面的步 |
| 运行中 | `fail` 且 **`retries ≥ 3` 或超过该步预算** | **已中止（FAILED）** | 预算按步不同：默认 15s / 第 3 步 60s / 第 6 步 30s / 第 9 步 25s；`reason` 会挂在标签与进度块上 |
| 运行中 | **游戏离开前台**（`PatrolRunner.onRound` ①） | **已暂停** | `paused = true`、`reason = 游戏不在前台，已暂停`；暂停期间**不动作**、**不计数**（`onRound` 早返回，`fail` 不会被调用 ⇒ **暂停期间不会中止**） |
| 已暂停 | **回游戏**（什么都点） | 已暂停（不变） | **不自动继续**（FR-05 明写）；菜单出现「继续｜停止」 |
| 已暂停 | 用户点「**继续**」 | 运行中 | **停在原来那一步**（不重跑）；⚠ 预算**不顺延**（见下"疑点"） |
| 已中止 | 用户点「**继续**」 | 运行中 | **从失败那一步**重试：`retries = 0`、`reason` 清空、**预算重新起算**（`stepEnteredAtMs = now`） |
| 已中止 | 什么都不做 | 已中止（不变） | **不自动重试整条流程**（硬性要求 6）；`fail` 在 FAILED 上是 no-op（不会累加） |
| 运行中 / 已暂停 / 已中止 | 区间终点步验证通过（`advance`） | **已完成（FINISHED）** | 先存结果快照（`PatrolResultSignal`）⇒ 再 `PatrolSession.stop()` ⇒ 标签**常驻**「已完成」 |
| 任意 | 用户点「**停止**」 | **没有在跑**（`state = null`） | `PatrolSession.stop()`：清 目标好友/目标区服、代次 `++`；日志 `停止：停在第 N 步`；标签回「待命」 |
| 任意 | **采集会话 / 常驻服务销毁** | 没有在跑 | 同上（"没人再做识别与点击 ⇒ 跑完的一并收掉"，避免留一个"看起来还在跑"的空壳） |

✅ **疑点已证实并修复（2026-10-01）**：真机实测"**暂停后点「继续」没有用**" —— 但机制比预判**更早发作**：
**不是**"立刻判超时中止"，而是 `lastActionAtMs` 没清 ⇒ `PatrolRunner` ⑤（本步已下过击 ⇒ 只等画面、绝不补点）
接手 ⇒ **死等到预算耗尽**（实录：继续后 `已等 28 秒` → `47 秒` → 60 秒中止）；同时确认**预算也没顺延**
（继续后从 28 秒起算，暂停时长被算进了耐心）。
**修法**：暂停与中止**两条来路统一口径** —— 都作废那一击（`lastActionAtMs = 0` + `stateAtLastAction = null`），
暂停分支再把预算顺延到此刻（见 `PatrolFlow.resume` 注释与 `progress.md` 第 390 条）。

### 3.1 三种"停手"的区别（暂停 / 中止 / 停止 —— 最常被混）

| | **暂停** | **已中止** | **停止** |
| --- | --- | --- | --- |
| 代码状态 | `outcome = RUNNING` ＋ `paused = true` | `outcome = FAILED` | `PatrolSession.stop()` ⇒ `state = null` |
| **谁触发** | **程序**：游戏离开前台 | **程序**：同一步重试满 3 次 **或** 超过该步时间预算 | **只有用户**（菜单「停止」）；"采集会话 / 常驻服务销毁"也会等价清空 |
| 流程还在吗 | **在**（停在同一步，进度 / 重试计数都留着） | **在**（FAILED 快照保留，步号 + 原因都在） | **没了**（清目标好友 / 目标区服 / 代次 ++）⇒ 想再跑要重新点菜单 |
| 会不会自己恢复 | 不会：回前台**不自动继续** | 不会：**不自动重试整条流程**（硬性要求 6） | —— |
| 点「继续」后 | 停在**同一步**接着跑（不重跑） | 从**失败那一步**重试：`retries = 0` ＋**预算重新起算** | 没有"继续"——等同重新发起一条 |
| 用户要做什么 | 几乎不用：回游戏点「继续」 | **先看原因**（验证不过 / 超时：登录慢、网络、切屏…）再决定 | 不用做什么（是你主动放弃） |
| 文案级别（ADR-008） | **L1**（"已暂停"要你点继续 ⇒ 需要动手） | **L1**（"已中止：原因"） | **L3**（只是告知："停止：停在第 N 步"） |
| 标签 | 「已暂停」常驻，菜单出现「继续｜停止」 | 「已中止」常驻（原因在菜单原因条与日志） | 回「待命」，整条标签摘掉 |
| 零点击 | 立刻停手 | 立刻停手 | 立刻停手 ＋ 流程清空 |

**一句话记忆**：**暂停** = "环境不允许（游戏不在前台），等你回来点继续"（**中间态**，进度留着）；
**中止** = "程序判定这一步走不通了"（**终局**，必须你点继续才回头，且回头也只重试那一步）；
**停止** = "人不让它跑了"（**清空**，没有回头路）。

⚠ **同名陷阱**：菜单「更多」里的「**暂停自动关弹窗**」是 **FR-01** 的开关（只停 FR-01 的自动关弹窗，
识别照旧、跑号不受影响），**与这里说的"跑号暂停"不是一回事**。

⚠ 另一条容易混的：**起点不成立 ⇒ 根本不启动**（`PatrolFlow.start` 返回 null，调用方如实提示），
这**不是**"启动后立刻中止"——菜单点了没动静 + 一行原因。
