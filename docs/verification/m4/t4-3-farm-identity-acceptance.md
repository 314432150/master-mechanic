## 3. 本次修掉的两个真 bug

### ① 刚进农场那一轮，农场锚点窗口没被灰度化

`CaptureService.anchorRegions` 只把"**上一轮状态**"的锚点窗口纳入灰度转换以省成本。而**刚进入农场的那一轮，上一轮状态还是「未知」** ⇒ 农场锚点（含头像判据）读到**全零像素** ⇒ 报出 0.19 这种几乎无关的分数（偏移 (0,0)，位置其实是对的）。

- 离线复现：同一产物 + 同一帧，用生产同源路径测是 **1.0000**，在线却是 **0.19** —— 差别只在这一处。
- **修**：`UiState.FARM` 的锚点窗口**常驻**转换（农场锚点只有几条几十像素的小窗口）。
- 教训：**判据类锚点必须在"进入画面的第一时间"就可用**，不能等下一轮。

### ② 标定页每写一次，产物里其它记录的窗口就被再收紧一次

`CalibrationStore.load` 早先返回"已收紧"的产物，而它**同时被标定页读写**使用 ⇒ `upsert` 把收紧值**写回盘** ⇒ 窗口 = 原值 ×0.6 / 次，直到撞上最小余量。

- 真机证据：写入自检报窗口 **117px**，几次写入后产物里只剩 **55px**（窗口/模板 3.00 → 1.41）。
- **修**：`load` 返回**原始值**；新增 `loadForRuntime`（load + 收紧）供采集侧（会话建立 + 重载）；界面侧继续用 `load`。
- **功能不受影响**：被污染到 55px 的窗口仍然可用（模板 39 + 每边 8px 余量，离线测 1.0，在线测 0.996~0.998）⇒ 用户**无需重框**。
- 产物里现有的 55px 是修复前写入留下的；修复后**不再继续收紧**（下次框选时复核）。
