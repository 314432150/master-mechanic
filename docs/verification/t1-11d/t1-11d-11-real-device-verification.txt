  旋转 90°/180°/270° 锚点分数 ≤0.333 → 「无旋转、等比缩放 + 居中」结论在真机会话样本上复核一致。

## 环境事实（记录备查）

1. **画布方向取决于「服务读取显示尺寸那一刻」的显示方向**：会话 B 中通过系统弹窗选「共享一个应用 → 王者荣耀」，
   系统先把 MM 带回前台、再切游戏 → 建会话读到的仍是竖屏尺寸（1440×3168）。
2. **vivo 会回写旋转设置**：`settings put system accelerometer_rotation 0` + `user_rotation 1` 被系统复位
   （复查为 `accel=1 / user=0`），强制旋转不生效；本次改用 `wm size 3168x1440` 临时把逻辑显示置为横屏建会话
   （等效于「建会话瞬间显示为横屏」，即真实触发条件），建会话后立即 `wm size reset`——
   收尾复查 `wm size` 为 `Physical size: 1440x3168`、`accel=1 / user=0`，设备设置已还原。
3. **横画布会话的帧到达率明显低于竖画布会话**（游戏前台静态启动页：会话 A 约 537–557 帧/10s，会话 C 约 3–4 帧/10s），
   识别轮次与状态判定不受影响（节流按时间驱动，2–5 轮/10s 正常）。作为环境事实记录，未深究（疑似与镜像面尺寸 /
   旋转状态下的合成时机有关）。
4. 重装 APK 会重置无障碍授权（vivo 行为，同 T0-2 记录），本次重新开启；会话 C 期间起前后无障碍服务曾短暂断开重连
   （18:01:29 一次），识别循环按 FR-09 冻结一轮后恢复。

- **T1-11a 待补项闭合**：真机横画布会话样本 37 帧（3168×1440）已归档，结论在真机会话样本上复核一致。
