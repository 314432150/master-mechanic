T2-5 离线验证说明（2026-09-13）

一、为什么要做这个验证
T2-5 把守护期待命期的搜索集合由 {启动页} ∪ {活动弹窗} 收窄为 {活动弹窗}——每轮都搜活动弹窗的 3 条 × 记录。
程序停在自己农场 / 好友农场 / 好友面板这些画面上时同样在搜这 3 条，因此必须证明：
**这些背景上不会误命中**（误命中会在没有弹窗的画面里判出「活动弹窗」，进而走 FR-01 点击链路；红线 3 / 7）。

二、方法与口径
- 探针：app/src/test/java/com/example/mastermechanic/recognition/PopupWatchProbeTest.kt（*ProbeTest，日常 -PfastTests 不跑）
  命令：.\gradlew.bat :app:testDebugUnitTest --tests "*PopupWatchProbeTest*"
- 帧：app/build/replay-work/set-20260912-03/（104 帧固定批次，含 manifest.txt）
- 产物：app/build/replay-work/t2-2-artifact.txt（设备产物副本，与识别侧同源）
- 口径：CalibrationData.toLoop() 的**生产默认**（= PopupWatchExpectedSignals，每轮只搜活动弹窗）
- 分组依据：manifest 的类别列 + 描述列（不靠帧名猜测）。
  注：同款弹窗的重复帧写作「大厅+…（同前）」，描述里没有"弹窗"二字，故类别列 neg-mask 一并参与判定——
  首轮跑曾因此把 2 帧弹窗错归为「大厅（无弹窗）」，表现为 5 条**假**误命中；修正分类后归零。

三、结果（完整逐帧报告见同目录 t2-5-popup-watch.txt）
| 分组 | 弹窗记录命中数 / 帧数 |
| --- | --- |
| 农场 / 好友农场 | 0 / 15 |
| 好友面板（列表 / 滚动） | 0 / 7 |
| 大厅（无弹窗） | 0 / 14 |
| 大厅 + 活动弹窗（命中对照） | 36 / 15 |
- 全批次每轮搜索条数**恒为 3**，不含 launch_start（口径生效）。
- 弹窗帧上命中的记录数分布为 2 ~ 3 条（4 种样式：万象棋 / 月度福利礼册 / 比翼连心 / 限时点券），
  其中「大厅+月度福利礼册」命中 2 条——与 T2-2 的逐样式归因一致。

四、结论与局限（如实记录）
- 结论：负背景（农场 / 好友农场 / 好友面板 / 大厅）**零误命中**，弹窗画面仍有命中 → 收窄唤醒集不引入误判。
- 局限 1：本批为 2026-09-12 单台设备（vivo V2463A）单人场景，弹窗样式覆盖 4 种，未覆盖全部活动样式。
- 局限 2：负样本合计 36 帧（农场 15 + 好友面板 7 + 大厅 14），**低于需求 §5 的 60 帧口径下限**；
  按 §5 要求的"上界表述"：真实误报率上界 = 1 − 0.05^(1/36) ≈ 8.0%。**不得据此声称"零误报"**。
- 局限 3：真机待命期行为（日志「本轮搜索集合变化」应恒为 3 条、弹窗出现当轮命中）仍需演练核对；
  实点链路核对随 T2-3e 进行。
